**What it delivers.** A library that reads Unity bundles, serialized files and typetrees exactly as UnityPy 1.25.2 with UnityPyBoost reads them, shaped for a batch engine and Python bindings. **How it was chosen.** Three candidate designs were written against the same brief: parity first, performance first, and fork economy first. Each was scored, and their factual claims were checked against rabex 0.2.1's source and UnityPy 1.25.2's (the wheel, and the UnityPyBoost C++ in its sdist). This plan starts from the parity-first design and takes from the other two what survived that check (section 0).

## 0. Decisions at a glance

1. **The core is a port of UnityPy's read and write rules, line by line, on raw bytes. This is an architecture choice, not a finding that rabex cannot be fixed.** Every format path (detection, bundles, SerializedFile, typetree nodes, both readers, the writer, the Environment) is written from the UnityPy function it mirrors, with a `// UnityPy <file>:<line>` comment on each rule. The P0 spike showed rabex fixable: with one header shim its dump of the corpus game and UnityPy's samples equals the oracle's in all 403,076 records (`docs/spikes/rabex.md` section 3), and the spike lists what a fork would change (its "Recommendation": `serde_typetree`'s read and write rules, panics into errors, allocation bounds, the metadata gates, a `(class, version)` cache key, liblzma, the writer, licence and provenance). The port is chosen because P1's other requirements are easier to meet in code shaped for them than by reshaping rabex's types: the API of section 3 (lazy files sharing `Bytes`, one meter per input, owned self-describing values the bindings convert); facts kept as read (raw bytes where rabex has strict UTF-8 `String`s, "absent" where it fills defaults, UnityPy's level jumps, which its recursive node trees refuse, and UnityPy's version arithmetic); and a zero-difference gate where every rule traces to a UnityPy line. rabex was to stay vendored for what the core does not replace (decision 2, since superseded).
2. **Superseded after P1:** `unityrs-tpk` now ports UnityPy's `helpers/Tpk.py` itself, keeping the fork's TPK patches F2-F11 (2.3's note), and the fork, its fence, `fork-check.sh` and the spike crate are removed. As P1 decided it: **rabex is vendored, as its own crate, pristine plus a ledger** (`crates/unityrs-rabex`, library name `rabex`; package A creates it, 7.2: until then rabex is a crates.io dependency of the spike crate only, and no fork is in the tree). The first commit is the unmodified crates.io source; every later commit is one numbered patch with its class and reason in `UPSTREAM.md`; `scripts/fork-check.sh` proves the crate equals the pristine source plus the ledger. Code the core supersedes (serde_typetree, rabex's object lookup and read paths) stays in the fork **verbatim and fenced**: no unityrs crate may call it. In P1 the fork supplies the TPK parser to `unityrs-tpk`; in P3 the UnityCN decryptor and the builders. This keeps re-vendoring and upstream offers cheap without letting rabex's types into the core. `docs/DESIGN.md` section 4 records the result: the core is a port of UnityPy's rules (Q1, decided).
3. **Buffers are `bytes::Bytes`, shared, never copied.** The input, each decoded block run, every bundle entry, every `SerializedFile`, every `TypelessData` value, every `vector<UInt8>` value and every string read from a file (`RawStr` is a `Bytes`: metadata strings, node names, `Value::Str`) are slices of one allocation. A decoded buffer carries the charge that paid for its whole capacity, and a decoder is charged before its output grows (3.15), so the books show exactly what is alive.
4. **Containers are lazy; the dump forces UnityPy's eager order.** A bundle reads its header, blocks-info and directory at open and decodes no data block. There is one layout, UnityPy's: the `b"".join` of every block's actual output. An entry's offset in it depends on the actual length of every block before it, so a lazy read first learns those lengths (a block not yet decoded is decoded with its output discarded, its length kept, each block once per open), then decodes the blocks it overlaps into a cached run (a block that two reads' spans share is decoded once per span, and every decode is charged to the input's meter and counted as decode work, 3.6). A read finds its blocks and its cached run by binary search, and counts those steps as decode work too (3.6, **Runs**). A lazy read that succeeds therefore returns exactly the bytes of the eager read, on every bundle, malformed ones included, and a block that fails before or inside the read fails it as it fails the eager load; a block that fails only after the read fails `load_all` and not the read, the one way a lazy read differs (3.13's difference (c)). `BundleFile::load_all` is UnityPy's load (every directory entry parsed, a failing entry fails the bundle).
5. **Typetrees compile once per type into a flat table** (kind, shape, align, dict key, minimum size per node), `Arc`-shared by every object of the type, as UnityPyBoost precomputes per node. The walker never compares strings.
6. **`Value` is UnityPy's dict model, owned and self-describing.** Float width, packed primitive runs, tuple versus list, bytes versus str, invalid UTF-8 and dict order live in the value. Dict keys are node ids into the node lists a `Parsed` carries: the root's list, then one per ref-type tree a `ReferencedObject` read through. That last part fixes a flaw in the fork-first design, whose keys could only name the root tree.
7. **Two readers and one writer, each a port of its own UnityPy code.** UnityPyBoost's reader for `byte_size > 0`, UnityPy's pure-Python reader for `byte_size == 0`, and UnityPy's pure-Python writer (UnityPyBoost has no writer), whose per-element alignment does not mirror the reader. No serde in the walker.
8. **UnityPy mode is the default everywhere.** That covers the float32 signalling-NaN quieting, the writer's alignment, the eager AssetBundle read at load, and no version fallback. `FloatMode::Lossless` and `WriteRules::MirrorReader` are opt-in and listed in `PARITY.md`.
9. **The common-string table a blob reads is the caller's TPK's**, built at run time as UnityPy's `get_common_strings()` builds it (112 strings in UnityPy 1.25.2's TPK, `tools/fixtures/tpk.py --survey`); without a TPK, the 108 of UnityPy's MIT enum, the only table committed. Corpus blobs use two of the four offsets past the 108, so the dump and the gates run with `--tpk` (fix pass 1 replaced the committed 112-entry table: nothing derived from a TPK is committed, Q2). rabex's 113th string stays out.
10. **No TPK in the core or the repository.** The core defines a provider chain keyed by `(class, packed version, script)`; `unityrs-tpk` loads a TPK from a path and implements it.
11. **No panics on untrusted input, bounded work, nothing global.** Clippy denies `unwrap`, `expect`, `panic`, `todo`, `unimplemented`, `unreachable` and indexing in the core (outside tests). Everything the core allocates in proportion to an input-chosen size is charged to the input's one meter before it is allocated, so one input holds at most `Limits::max_input_memory` plus a stated constant, however many files it holds and however often it is read (3.15); every input-chosen count grows a table only as the bytes behind it are read, never sizes an allocation; arithmetic on input integers is widened or checked, as Python's integers never overflow (positions are signed `i128`); and no step is worse than linear in its input, up to a sort's log factor (one object's read or write is linear in its bytes, its tree and its file's ref-type list, which each object's read consults again, as UnityPy's does, plus the values it counts against `Limits::max_values_per_object`, which bounds what its bytes do not: the children a read skips, and a value a tree that repeats a name has written once for each child of the name: 3.10). The core spawns no threads and never waits (a source scan checks both, 4.1). No lock is held across user code but a budget's, whose contract forbids it to block or call the core, and no lazy value is computed while its cell is locked (3.16). Every public type is `Send + Sync`, checked at compile time, and a test fails when a public type is added without the check.
12. **The canonical dump lives in `unityrs-dump`, on the public API only.** The core takes on no JSON, sha256 or gzip. If the dump needs a fact the API does not expose, the API is incomplete.
13. **Five work packages run in parallel after this scaffold** (section 7): A the fork, tables, TPK and licences; B the typetree compiler, readers and writer; C streams, versions, detection, codecs and files; D providers, objects, the container and the Environment; E the dump, the CLI and the gate.

### 2.4 The fork's mechanics

(Superseded with the fork: 2.3's note.)

- **F0, the pristine import.** The crates.io tarball's `src/`, `LICENSE-MIT.md` and `LICENSE-APACHE.md`, unchanged (tarball sha256 `d5f8c39f8069c0dc6d01d5435bd21153fda86b2e01af5fea9b5ddfe0716c3d58`). Only `Cargo.toml` is ours: package `unityrs-rabex`, `[lib] name = "rabex"` and `doctest = false`, `license = "MIT"`, `publish = false`, no `embed-tpk` feature and no `resources/` (the TPK and its dumps never enter the tree), the compression features the TPK reader needs, and its own `[lints]` table (it does not take the workspace's pedantic lints; upstream's style is kept). `doctest = false` because rabex 0.2.1's own doc examples cannot pass in the fork and its source cannot be edited: three `no_run` examples import `anyhow`, which is not a dependency (`src/tpk.rs:7`, `files/bundlefile/builder.rs:17`, `files/serializedfile/mod.rs:10`), and two call `embedded()`, which exists only under the `embed-tpk` feature this manifest leaves out (`src/tpk.rs:25-34`, `typetree/typetree_cache.rs:24-26`), so `cargo test --workspace` would fail on them. Its unit tests still run.
- **The ledger**, `crates/unityrs-rabex/UPSTREAM.md`: one row per patch with id, commit subject (`rabex F<n>: `, which `fork-check.sh` matches one to one to the fork's commits, since a hash changes on every rebase and merge), rabex lines touched, class, upstream status and, for a non-upstreamable patch, why. Classes: **U** upstreamable bug fix or additive API; **P** policy (licence, provenance); **C** UnityPy compatibility, not upstreamable. P1's patches:

## 3. The API

### 3.1 Principles

- **As read.** Every field UnityPy keeps is exposed as read: `Option` where UnityPy has no attribute, raw bytes where UnityPy keeps a surrogate-escaped `str`, the stored integer width. The dump is written from the public API, so a missing fact is a missing accessor.
- **Handles.** Files are `Arc`s of immutable parsed data (`File`, `Arc<BundleFile>`, `Arc<SerializedFile>`); an `ObjectRef` is an `Arc` on its file and the index of its row, which it reads from the file's table on demand, so a handle copies nothing and a caller may keep or clone millions of them without duplicating the table the parse charged (`object::tests`). Everything lazily computed sits in a `OnceLock` filled only through `once::get_or_publish`: the value is computed with no lock held and then published by a move. Two threads that ask at once may both compute it; the first to publish wins, and the other's value and its charges are dropped (3.16). A fallible value goes through `once::get_or_publish_result`, which publishes the value or an error the input decides, and never a **transient** one (`CellError::is_transient`: a budget or meter refusal, an I/O failure, a provider's failure). A refusal depends on what else is held at that moment (two threads computing one value at once can cause it), so keeping it would fail every later ask of a shared dependency for the handle's life; it is returned unpublished, and the next ask computes again. A computation that ends unpublished is work the next ask repeats, and the input chooses how often it asks (a compile that alone needs more than the meter is asked by every object of its type), so when the input's own meter refused it (`CellError::is_meter_refusal`, `LimitKind::InputMemory`) every byte the meter granted it, on its own thread, counts as its open's work (3.6's `max_decode_work`), and once that allowance is used up an ask keeps a `DecodeWork` refusal, which is not transient, instead of computing (`once::tests::a_compute_refused_on_its_own_stops_at_the_work_bound`, `serialized::tests::a_compile_the_meter_refuses_on_its_own_runs_a_bounded_number_of_times`: 200 asks of a compile that needs twice the meter run it 4 times). Nothing else counts (round 6): grants another thread made on the same meter meanwhile are that thread's (`limits::GrantScope`, a per-thread tally that allocates nothing; `once::tests::another_threads_grants_are_not_a_failing_computations_work`), and a budget refusal, an I/O failure or a provider's failure depends on what else is held or on caller code, so counting it would let contention poison a valid shared dependency for the handle's life (`once::tests::budget_refusals_count_no_work_and_the_read_succeeds_once_the_pool_empties`: 50 refusals at fifteen times the allowance, then success once the pool empties). Those repeat as often as the caller asks, which the engine bounds (4.1). A kept error is charged to the input's meter for the heap it owns (`CellError::heap_bytes`, `once::KeptError`), and every later ask gets a clone that shares it: `Error` and `ParseError` hold their messages and nested errors in `Arc`s, so a clone allocates nothing (`files_memory.rs` keeps a thousand answers of a failing entry and holds no more heap). A compute has no side effect but its charges: what follows from a value (registering a nested container's entries) is done from the published value.
- **Context.** One `Arc<FileContext>` per load carries version policy, float mode, writer rules, providers, codecs, decryptor, budget and limits into every file of the load. The load also makes the input's meter (3.15), which every parse is passed and every file keeps (`File::meter()`).
- **Errors, not panics.** Every fallible call returns `Result<_, Error>` or a narrower error with a structural kind; the dump never parses message text.

### 3.2 Strings

- `RawStr` (`raw.rs`, scaffold): the bytes UnityPy decoded with `surrogateescape`, kept as bytes, and a `Bytes`: a string read from a file is a zero-copy slice of the file's buffer (`RawStr::from_shared`), a common string is static, and only strings the core computes allocate, each charged to the input's meter as it is made (`RawStr::charged`: `heap_cost` of the bytes plus the owner record): the decimal string of an unknown common-string offset (3.8), `pystr`'s `py_lower`, `simplify_name` and `clean_external_path`, which take the meter, and a resource candidate's whole name (`env::Candidate::joined`, `RawStr::charged_concat`). A lookup by a name an input chose (`Registry::get`, `Environment::get_cab`, `find_file`) takes the name as a `RawStr` and the meter of the file that chose it, so the lowered key it builds is charged while the lookup runs, and a name already in its simplified form is not copied. `to_str()` gives `Some` only for valid UTF-8 (a surrogate code point's three-byte encoding is invalid, as in Python). `Display` escapes. Metadata strings, node names, node types, container paths and `Value::Str` are all `RawStr`, so a typetree row that names a long local string costs a handle, however many rows name it.
- `pystr.rs` (D): `py_lower` is `str.lower()` on a surrogate-escaped string: valid UTF-8 runs lower with full case mapping using Rust's tables except where `tables::lower_exception` gives Python 3.11's answer, and a capital sigma by its `Final_Sigma` context read with the generated Unicode 14.0 classes (`tables::is_sigma_cased`, `tables::is_case_ignorable`; Rust's own tables are newer); invalid bytes pass through. `lower_eq` compares without building the lowered string and allocates nothing. `ntpath_basename` (after `splitdrive`: a drive letter or UNC prefix is dropped), `ntpath_splitext` (leading dots are not an extension), `simplify_name` (`basename(name).lower()`, `environment.py:357-363`) and `clean_external_path` (`classes/PPtr.py:68-73`).

### 3.3 The stream reader

`stream.rs` (C) is the memoryview `EndianBinaryReader` (`streams/EndianBinaryReader.py:230-285`) over a slice with its own cursor. **The position is signed (`i128`)**, as a Python `Position` is an unbounded integer that UnityPy moves with plain arithmetic: it goes negative or past the end, and the reads after it follow Python's rules, which the scaffold implements once as free functions and an oracle fixture pins (`tests/fixtures/scaffold/reader.json`, written by `tools/fixtures/scaffold.py`, replayed by `tests/scaffold_fixtures.rs`):
- `read(n)` is `py_read`: a Python slice, negative indexes from the end, a reversed range empty; the position moves by `n` whatever the slice held (size -1 sets it to the end, so `read(-1)` at 12 of 10 bytes leaves 10);
- the 16-byte fields UnityPy takes with `read_bytes(16)` (an external's `guid`, a type record's `script_id` and `old_type_hash`) are that slice as it is, so near the end or at a negative position they load short, as UnityPy loads them (`Reader::read_short_array`, a `stream::ShortArray<16>`; `files_fixtures.rs` a_short_guid_or_hash_read_loads_as_unitypy_loads_it);
- every fixed-width read of 2, 4 or 8 bytes the reader's own methods make (`reader.read_int()`) is `struct.unpack_from(view, Position)` (`:340-343`), `py_unpack_from`: a negative offset counts from the end and must leave the whole read before the end; the position moves only on success. The pure-Python typetree reader's primitive nodes are the exception (3.10): they read through the base class's functions, `unpack(fmt, read(n))`;
- a one-byte read (`read_u8`, `read_i8`, `read_bool`) is `unpack(fmt, read(1))` (`:91-95`): the `py_read` slice must hold one byte, and the position has moved even when it raises (at -1, `view[-1:0]` is empty);
- `align(n)` is `py_align`, Python's floor modulo from the start of the slice, with no bounds check (-7 aligns to -4);
- `read_string_to_null` is `py_string_to_null` (`:275-284`; the oracle feeds UnityPy bytes: `tools/parity/dump_records.py`'s `_dump_input`): `re.search` clamps both bounds of the `STRING_TO_NULL_WINDOW = 32_767`-byte window into the buffer, so a negative start searches from 0; found, the string runs to the NUL, which is consumed, and the position is the absolute index after it; not found, it raises when `pos + 32_767 >= len` and otherwise returns `read(32_767)`, a slice from the position that may hold a NUL or nothing;
- a read UnityPy refuses returns `Error::OutOfBounds { what, pos, need, have }` (its `struct.error`/`EOFError`); `read_bytes` returns a borrowed slice; nothing pre-allocates from a length.

The positions that go negative, each a named test of its owner: `parse_blob` with a negative `node_count` or `stringbuffer_size` (3.8); a `SerializedFile` below format 9 whose `metadata_size` exceeds `file_size` (`SerializedFile.py:266`); blocks-info at the end with `compressedSize > Length`, read at `Length - compressedSize` (`BundleFile.py:135`, so `view[L-c : L]`); the pure-Python reader after a negative `TypelessData` length (3.10); a format-22 `byte_start + data_offset` below 0 or above `i64::MAX` (`ObjectInfo::byte_start` is `i128`); a `guid`, `script_id` or `old_type_hash` read at a negative position, which loads short (the bullet above).

**Counts.** UnityPy builds every metadata table with `range(count)` (`SerializedFile.py:282-308`, `BundleFile.py:145-165`), so a **negative count is zero records, not an error**, and a huge count fails only when the bytes run out. Parsers therefore grow tables record by record, reserving at most `min(count, remaining / min_record_bytes)` and never more than the input's meter still allows, so a table's length is bounded by the bytes that back it. `read_i32_array` is the exception: its `struct` format rejects a negative count (`EndianBinaryReader.py:258-264`), and it checks `4 * count` against the bytes before allocating; it takes the input's meter and returns a `MeteredVec<i32>`, charged before it is allocated (scaffold, implemented: `stream::tests::read_i32_array_reads_as_unitypy_and_charges_the_meter`, recorded from UnityPy; round 5: it returned a plain `Vec`, the one input-sized table a parser would have held uncharged). The bytes bound a table's length but not its memory, since a record can be one input byte (an external below format 5 is a lone NUL) and its parsed form far larger, so every table is a `limits::MeteredVec` on the input's meter: its capacity is charged before each growth (3.15), and a growth the meter refuses stops the parse with `LimitKind::InputMemory`. Two `SerializedFile`s of one input, or one entry parsed twice, charge the same meter.

### 3.4 Versions

`version.rs` (C) ports `helpers/UnityVersion.py`.
- `UnityVersion::parse(&RawStr)` matches `^(\d+)\.(\d+)\.(\d+)(.+?)?(\d+)?(.*)$` (UnityPy\'s pattern, `helpers/UnityVersion.py:7-10`; a lazy type group, which takes exactly the one non-digit the greedy `build` group leaves, so it accepts what `(.)?` would, with the same groups, C request 2) with Python's `re` (`\d` is any `Nd` digit via `tables::nd_digit`, DOTALL). The type character lowers to `a` 0, `b` 1, `c` 2, `f` 3, `p` 4, `x` 5, anything else 255; none at all is `f`. `packed` is `major<<48 | minor<<32 | build<<16 | type<<8 | number` as an **unbounded OR**: `Packed::Small(u128)` while it fits, `Packed::Big` beyond. Equality, hashing and ordering are on `packed`, as Python's `int` (two raw strings may pack equal). `raw()` keeps the string **without a copy**: `parse` and both chains take the file's own `RawStr` (a slice of its buffer, the parent bundle's `version_engine`, or the policy's fallback) and keep a clone, a reference count, and so does `VersionError::NoMatch`; a version string can be 32,767 bytes (`read_string_to_null`'s window, with the pattern's DOTALL `(.*)$`) and every parse of an entry keeps its own version, so a copy would be an uncharged allocation per parse (`version::tests::the_chains_take_the_files_string_so_a_version_keeps_it_uncopied`). The one heap a version owns is a `Packed::Big`'s limbs (`UnityVersion::heap_bytes`), which the file that keeps the version charges with its handle (3.15).
- **Python's digit limit.** Each group goes through Python 3.11's `int()`, which refuses a string of more than 4,300 digits (`sys.get_int_max_str_digits()`, `version::PY_INT_MAX_STR_DIGITS`; leading zeros and non-ASCII `Nd` digits count). `from_str` then raises `ValueError`, as for a string that does not match, so a group of 4,301 digits is `VersionError::NoMatch` in both chains (probe: 4,300 digits parse in every group, 4,301 raise). A 4,300-digit major, minor or build parses, but its packed integer has more than 4,300 digits and the oracle's `json.dumps` then raises, so no oracle dump can hold one (`docs/CANONICAL_DUMP.md` section 7); the core reports the exact integer.
- **From a TPK** (scaffold, implemented): `UnityVersion::from_packed(u64)` is UnityPy's `UnityVersion(int)` (`helpers/Tpk.py:464`), with an empty `raw()`, and `packed_u64` returns a packed value that fits; with the ordering this is what `unityrs-tpk` needs to pick an entry (`Tpk.py:472-481`) before C lands.
- **Chain 1, the bundle** (`files/BundleFile.py:523-536`), `resolve_bundle(engine: &RawStr, policy)`: the engine string; when it does not parse or its 16-bit major is 0, the fallback; no fallback is `VersionError::NoFallback`. It decides `flags_class` (`:113-121`) and `uses_block_alignment` (format 7 and up, or 2019.4.15 ≤ engine < 2020 at format 6; `:129-131`).
- **Chain 2, the SerializedFile** (`files/SerializedFile.py:351-360`), `resolve_serialized(own: &RawStr, parent_engine: Option<&RawStr>, policy)`: its own string (format 7 and up); when empty or `0.0.0`, the parent bundle's raw engine string (a `WebFile` parent gives none); when still empty or `0.0.0`, the fallback; then `parse`, which fails on whatever string that chain produced if it does not match.
- `VersionPolicy { fallback, force_bundle, force_serialized }`: `fallback` is UnityPy's `config.FALLBACK_UNITY_VERSION` (default `None`, as UnityPy); the two forces are unityrs options for broken headers and are reported in `ResolvedVersion::source`.

### 3.5 Detection and `parse_file`

`detect.rs` (C): `check_file_type(data, limits)` implements CANONICAL_DUMP section 4.2's eight rules in order (`helpers/ImportHelper.py:44-125`), including: a 20-byte file with no NUL raises; the U+00FA signature as UTF-8 bytes; zip only when byte 4 is NUL; gzip must inflate in full, every member, CRC and size checked, trailing zero bytes allowed, bounded by `Limits::max_inflate` (a `LimitKind::Inflate` refusal, `DetectError::InflateLimit`; the spike's detector inflated only 20 bytes; that is wrong for rule 7). A container's entry is detected by `check_entry_type(data, limits, meter)`, which also counts every byte it inflates, the chunk that passes `max_inflate` included, as the open's decode work (3.6): UnityPy detects every directory row's bytes, and many rows can name one small stream that inflates to the bound. The full inflate is UnityPy's, not a unityrs policy, though `ImportHelper.py:77-83` asks for only 20 bytes: it reads them through a streaming `EndianBinaryReader` whose `read_string_to_null` tests `Position != Length` on every byte (`EndianBinaryReader.py:136-144`), and that `Length` is `seek(0, 2)` on the `GzipFile` (`:303-308`), which decompresses to the end of the last member. The oracle raises `BadGzipFile` on a bad CRC, `zlib.error` on a corrupt second member and `EOFError` on a truncated stream, each after a valid `UnityWebData` prefix. Detection inflates into a fixed scratch buffer of at most 64 KiB and keeps only the first 20 bytes and the stream's length, so it charges nothing (the scratch is part of 3.15's constant); brotli at offset 0x20; the SerializedFile header read big-endian whatever its endian byte says. `parsed_as(ty, name, is_entry)` is `parse_file`'s naming rule (`ImportHelper.py:127-156`): an `AssetsFile` named `*.resS`, `*.resource`, `*.config`, `*.xml` or `*.dat` (case-sensitive) stays raw; a zip is `Zip` only for an input.

`files::parse_file(name, data, ty, parent, meter, ctx)` (C) builds the `File` the type and name rule say, charging everything it keeps to `meter`, the input's. A container entry that is itself a container parses one level deeper (`Parent::depth`), refused past `Limits::max_container_depth` (`LimitKind::ContainerDepth`). P1 refuses `WebFile` (`Unsupported::WebFile`).

### 3.6 Bundles and codecs

`files/bundle/` (C) ports `files/BundleFile.py`, lazily:
- `BundleFile::open` reads the header, blocks-info and directory only. `header()` exposes every field the dump's L1 writes (signature, format, both version strings raw, the resolved engine version, `data_flags`, `flags_class`, `block_alignment`, `encrypted`, `hash`/`crc` for the web/raw layout). `uncompressed_size()`, the sum of the **declared** block sizes, is known before any decode (for a caller that plans with it, 4.1); the actual decoded total can differ (LZMA ignores the declared size, LZ4 may decode short, a stored block yields its stored bytes when slot 0 holds the built-in stored codec and what a caller's codec registered there makes otherwise, a truncated block yields what is there), and the limits and the budget follow the actual bytes (below).
- The rules, each with a test: the extra byte after the data flags only for non-UnityFS signatures (`BundleFile.py:104-106`; rabex reads it for UnityFS); the flag set by engine version (`:113-121`); the decryptor check **before** the 16-byte alignment (`:123-124`, then `:129-131`); blocks-info at the end read at `len - compressed` (`:134-137`); padding at the start only under the new flags with 0x200 (`:170-171`); a truncated block read short and decoded as it is, its actual length being the dump's `compressed`.
- **One layout: UnityPy's joined data.** UnityPy always decodes every block and reads entries from `b"".join` of their **actual** outputs (`:173-186`); there is no declared layout to fall back from. Block `b` starts at the sum of the actual lengths of blocks `0..b`, so an entry's bytes depend on every block before it, not only on the blocks it overlaps. The bundle keeps one `OnceLock<u64>` per block for its actual length. A length is known at open for a stored block (its bytes read) when slot 0 holds the built-in stored codec (`Codecs::stores_as_is`) and those bytes are within `max_block_output` (a stored block meets the cap on every path, as it does through its codec); otherwise only by running the block's codec.
- **Lazy reads.** Before `entry_bytes(i)` or `entry_range` returns bytes ending at joined offset `X`, every block that starts below `X` has a known length: a block still unmeasured that lies wholly before the read is decoded with its output discarded (a scratch buffer of its own, its length kept), and the blocks the read overlaps are decoded into a run cached in the run index (a run is `Bytes` carrying its charge; see **Runs** below for a block two spans share). A measuring decode is charged while it runs and returns its charge after. A read whose bounds depend on the total length (a negative offset, a size of -1, a stop past the end) measures every block. Every entry is a zero-copy slice of its run. `entry(i)` parses once per handle, computed outside its cell and then published (3.1). There is no switch of layout after bytes were served, so a lazy read that succeeds returns exactly the slice of `load_all`'s joined data on every bundle, malformed ones included, and a block that fails before or inside the read fails it as it fails `load_all`; a block that fails only *after* the read fails `load_all` and not the read (3.13's difference (c)). **Block outcomes are kept**, failures included: each block's cell holds its actual length or the error its decode gave, so a failing block is decoded once and every later read that needs it fails at once, as UnityPy fails once; a refusal that depends on what else is held (the meter, the budget) is not kept (3.1). On a well-formed bundle read in directory order the measuring costs nothing (the earlier runs are already cached); reading a later entry first costs one discarded decode of the blocks before it.
- **Entry slicing.** An entry is `reader.Position = offset; reader.read(size)` on the joined data (`files/File.py:78-81`), and the memoryview `read` is a Python slice (`EndianBinaryReader.py:248-255`): size 0 is empty, size -1 reads to the end, any other size is `data[offset : offset + size]` with negative indexes counting from the end and a reversed range empty. `stream::py_read` implements that arithmetic once (in `i128`, so no `i64` offset can overflow), and the bundle, `parse_blob` and the pure-Python reader use it.
- **Eager.** `load_all()` decodes every block in order and parses **every directory entry** in directory order, a path repeated in the directory included (its earlier entry is parsed and can fail, though the `files` dict keeps the later one), and returns the first error, which is UnityPy's behaviour (a failing entry fails the bundle).
- **Codecs** (`codec/`, C): **None** returns the stored bytes, as a zero-copy slice of the input; **LZMA** (`helpers/CompressionHelper.py:17-44`) is a raw LZMA1 decode of the 5 property bytes plus the rest, **run to the end of the input, the declared size ignored**, capped by `Limits::max_block_output` (fewer than 5 input bytes is `struct.error`); **LZ4/LZ4HC** (`:83-94`) is `lz4.block.decompress(data, uncompressed_size)`: the declared size is a **maximum**, a shorter output is accepted, a longer one raises (the performance-first design's "must equal" is wrong), and an empty input raises whatever the declared size; **LZHAM** and unknown ids raise (`:234-235`, `BundleFile.py:515-521`; `CompressionFlags` is an `IntFlag`, so any id constructs and the map lookup is what raises). `Codecs` is a 64-slot registry (the flags' low six bits) that a user may extend; only canonical ids name a slot (`Codec::Other(5..=63)`; `Other(1)` is not LZMA, and `set` hands a non-canonical value back); `BlockDecryptor` runs before decode (UnityCN: P3).
- **LZ4 acceptance is liblz4 1.9.4's** (`LZ4_decompress_safe` under python-lz4 4.4.4), not `lz4_flex`'s. They disagree both ways: liblz4's end-of-block conditions (a literal run ending within the last 12 bytes of the declared size or the last 8 bytes of input must be the last sequence and end exactly at the end of input; a match must end at least 5 bytes before the declared size; the length-extension guards) refuse blocks `lz4_flex` decodes, and liblz4 decodes a match at offset 0 (a run of zeros) that `lz4_flex` refuses. The oracle fixture `tests/fixtures/scaffold/lz4_blocks.json` (813 blocks around liblz4's end-of-block conditions, each decoded at up to 11 declared sizes around its real output, with liblz4's verdict and output; `tools/fixtures/scaffold.py` builds them) is the codec's acceptance test, and `tests/scaffold_fixtures.rs` pins that `lz4_flex` alone fails it. C checks the sequence stream against these conditions before (or while) `lz4_flex` decodes, and handles offset 0 itself; the dependency list stays as it is.
- **A codec writes into a `DecodeBuf`** (`budget/`, scaffold, implemented): `BlockCodec::decode(input: &Bytes, uncompressed, out: &mut DecodeBuf) -> Result<Decoded, Error>` either appends its output (`extend_from_slice`, or `grow_zeroed` then `truncate`) and returns `Decoded::Written`, or leaves `out` empty and returns `Decoded::Input(range)`, a range of its input (the stored codec). **A codec cannot return bytes of its own**: a buffer a registered codec allocated (a P3 Python decompressor's `bytes`) would be input-sized memory in the bundle's runs that no meter charged (round 5), so the trait takes a range, and its output otherwise goes through `out` (a `compile_fail` doctest pins the old `Option<Bytes>` form out). **Every block is decoded through `codec::decode_block(which, codec, input, uncompressed, out, cap)`** (scaffold, implemented), which begins the block's segment at `cap` and checks what came back: a range must lie within the input, with the segment left empty, and fit `cap` as if written, or the codec's call is `Error::Decompress` (a range longer than `cap` is `BlockOutput`); it returns the zero-copy slice (`codec::tests::a_codecs_range_is_checked_and_sliced_from_its_input`). A `DecodeBuf` is made on the input's meter (`DecodeBuf::new(meter, initial, cap, kind)` charges its first allocation before making it) and holds one segment per block: `begin_block(cap, kind)` starts the next block of a run, so each block is capped at `max_block_output` (`LimitKind::BlockOutput`) on its own. Every growth first checks the segment's cap, then charges the new capacity to the meter (which books it with the budget), and only then grows; capacity doubles while the meter allows it and otherwise grows to exactly what is needed, so a budget that fits the output is not refused for the doubling. A dropped `DecodeBuf` returns its charge, and `into_bytes` hands the charge to the `Bytes` (the owner record charged too). So an LZMA block declared at 1 byte that decodes towards 1 GiB is refused at the first growth the meter or the budget does not allow, before the bytes exist (`tests/decode_alloc.rs` watches the heap with a counting allocator: a refused 64 MiB growth allocates nothing, on a budget refusal, on a meter refusal and in `new`).
- **Limits on actual bytes.** `max_block_output` caps each block's actual output (blocks-info's included); the input's meter caps everything decoded, at its actual length, whichever decode made it: a first decode, a measuring decode, a re-decode of a block two spans share, a re-decode after the handle was evicted and opened again (3.13). There is no separate declared-total limit: the meter sees the actual bytes as they grow, and `uncompressed_size()` is the declared total a caller may plan with. Blocks-info's rows grow with its bytes (3.3).
- **Decode work.** Memory returns when a run drops; work does not. Every byte a block decode writes (first, measuring, repeated, a decode that fails after it wrote), whether or not its buffer grew for it, also counts toward the input's decode work (`Limits::max_decode_work`, default 32 GiB, `LimitKind::DecodeWork`), which is not returned while the input is open, so reads that decode, drop and decode again (thousands of blocks that each decode to the block cap, measured and dropped by a lazy read of the last entry; a block that fails after it wrote) stop at that bound instead of running without end under a meter that never fills (`budget::tests::a_decode_repeated_for_every_read_stops_at_the_work_bound`, `limits::tests::decode_work_is_counted_and_never_returned`). Every byte a bundle entry's gzip detection inflates or reads counts toward the same allowance (3.5), so the rows of one open that name one stream inflate it no more than that bound allows, and the detection that passes it is the open's `DecodeWork` limit (`tests/bundles/memory.rs` gzip_detection_across_the_rows_of_one_open_draws_on_its_work, a_detection_refused_at_its_inflate_bound_still_draws_on_the_opens_work, a_detection_counts_the_stream_it_reads_not_only_what_it_inflates). So do the bytes a parse searches or indexes (each metadata string's search, a typetree blob's one pass over its string buffer, whose NULs then answer every row by a binary search, and a format-below-16 file's type index, where UnityPy scans `types` per object), and every byte the meter granted an entry parse that ends in an error its cell keeps: each directory row is its own cell, so K rows over one failing span would otherwise repeat the parse K times, uncounted (round 4; `tests/bundles/work.rs` rows_over_one_failing_entry_stop_at_the_opens_work, an_entrys_blob_strings_cost_one_search_of_its_buffer_whatever_its_rows), and every byte the meter granted a read of a file's AssetBundle beyond the container it keeps (all of it when the read fails): K rows over one span that parses would otherwise build and drop its value K times (round 5; `tests/bundles/work.rs` rows_over_one_asset_bundle_stop_at_the_opens_work, a_container_read_counts_what_it_was_granted_beyond_its_container). Every byte of a block a codec reads counts too, before the codec reads it, the built-in stored codec excepted (it names its input, and what is copied from it counts as written), as credit for what the decode writes (`DecodeBuf::prepay`), so a decode counts the larger of its stored bytes and its output, and a compressed block that decodes counts its output as before; a decode the budget or the allocator refuses gives back what its writes did not use (`tests/bundles/nested.rs` a_decode_counts_the_larger_of_its_stored_bytes_and_its_output). LZ4 scans a whole block before it writes a byte, so a block that fails at its end wrote and counted nothing, and every directory row over a nested bundle opens it anew: K rows scanned its failing blocks-info or block K times, uncounted (review round 6). And directory rows with the same offset and size whose names agree on the raw-suffix rule (`detect::parsed_as`) read the same bytes and parse them alike: they are twins, and a failure the input decides, kept for one, is every twin's answer under its own name, the first twin's cell holding it, so K twins parse their span once (round 6; `tests/bundles/nested.rs` rows_over_one_failing_nested_bundle_scan_it_once, rows_over_spans_of_a_failing_nested_bundle_stop_at_the_opens_work, reads_of_failing_blocks_through_rows_stop_at_the_opens_work, rows_whose_names_disagree_on_the_raw_rule_are_not_twins). Work refused after it was done (a string search, what a gzip detection read or inflated before a failure) is counted all the same, so every later piece of the open's work is refused (round 5's sweep). A `DecodeBuf` counts every write of a block's segment (`extend_from_slice`, `grow_zeroed`; room made ahead by `new` or `reserve` is memory, counted when written) in one atomic check-and-add (`Meter::count_decode`), placed for a write that grows the buffer once the meter and the budget granted its memory and before it allocates, so a buffer sized up front, a scratch buffer reused across decodes and output written in small pieces count every byte (round 6: only growths counted, so all three decoded without bound; `budget::tests::every_byte_written_counts_whatever_the_buffer_already_holds`), a refused growth decodes nothing and counts nothing (a transient refusal never uses the allowance up, and the same read succeeds once there is room: `budget::tests::a_refused_growth_counts_no_work_and_the_read_succeeds_once_there_is_room`), a growth the bound refuses returns its charge and allocates nothing, and decodes on several threads never pass the bound together (`budget::tests::decodes_on_several_threads_never_pass_the_work_bound_together`: eight threads each granted 1 MiB of memory at once, against 4 MiB of work, decode four). The count is the meter's, and **a meter is one open of its input**: every file of the open (its entries and nested bundles) shares it, and the Environment opens an evicted dependency again on `Meter::reopen` (3.13), a new meter on the same memory account with its own allowance, so eviction churn costs work in proportion to the reads that cause it, while a handle of the old open that someone still holds (a nested bundle a resource read kept) goes on counting against the old open's allowance, which nothing resets (`limits::tests::a_reopen_has_its_own_work_and_shares_the_inputs_memory`). The same allowance counts what a lazy computation the meter itself refused was granted on its own thread (3.1). The default is four times `max_input_memory` because a lazy read of a bundle whose entries do not overlap decodes a block at most four times (measured; decoded for the entries wholly inside it; decoded again for each of the two entries that straddle its edges, **Runs** below), where UnityPy decodes it once, each decode counting its output (or its stored bytes, for a block they outnumber).
- **Budget.** The meter books every charge with `ctx.budget` under its `Reservation` (`Input` for what the caller loads, `Dependency` for what the Environment loads to resolve a pointer or resource), so a refusal names the pool that refused (`ChargeError::Budget`, `Error::Budget`) apart from the input's own bound (`ChargeError::Limit`, `LimitKind::InputMemory`).
- **Runs.** A run covers the blocks one read overlaps, contiguous, and is cached by its block span; a span of stored blocks that are their own bytes (`Codecs::stores_as_is`) is one slice of the input, cached as a run too. A read whose span a cached run covers slices it; any other read decodes its own span into a new run, so a block shared by two spans (a straddling read) is decoded twice and charged twice. `load_all` decodes every block into one run, so under `Eager` the runs hold exactly the joined data. `entry_range` (a `.resS` read) is a read like any other: it measures, serves from a covering cached run, and otherwise decodes its span into a run it caches, so N ranges in one block decode it once. A hostile directory whose spans nest or overlap makes lazy reads decode the same blocks again and again; each run is charged, so it stops with `InputMemory` at the meter's limit (3.13's difference (d)), where `Eager`'s one run fits. A run is decoded with no lock held and then published into the run index under its mutex; that growth is charged, so the one caller code that runs under the mutex is the budget, whose contract forbids it to block or call the core (3.16).
- **What a read costs** (`files/bundle/index/`, `runs.rs`). Two tables. *The known prefix*: blocks `0..P` whose lengths are all known and not errors, with where each ends in the joined data (the prefix sums of their actual lengths), one row per block, charged at open with the other per-block tables. It only grows: a read extends it in order past its own end, so each block is learned once per open; and it takes no lock (a row is written before the count passes it, and two threads that learn one block write one value, a block's length being published once). *The run index*: the cached runs keyed by first block in a B-tree, charged a share per run (a fifth of a leaf and a thirtieth of an internal node, the Environment registry's argument, 3.13) and its root leaf once. No run contains another (a run is published only when no cached run covers its span, and publishing drops the runs it covers, after the lock), so the run that starts last at or before a span's first block is the only one that can cover the span, and the runs a new one covers follow each other from its first block. A read: (1) finds its first block (the first that ends past its start) by binary search of the prefix, or, when the prefix ends at or before the read's start, extends it a block at a time (a block not yet measured is decoded, and kept as the run's start when it reaches the read); (2) finds its span's end (the last block that starts below its end) by binary search of the prefix from that block, or extends the prefix to it, decoding the span into a new run from its first unknown block (its known blocks decoded again first); (3) searches the run index once; (4) checks each block of the span for a stored slice; (5) publishes (one search, the covered runs dropped). So a read costs O(log B + log R) steps besides the blocks it learns or decodes, for B blocks and R cached runs, where every read walked the blocks from block 0 and scanned every run (fix pass 4's sweep: K rows over B blocks cost K x B steps, quadratic and counted by nothing). **Every step counts toward the open's work** (`max_decode_work`, `DecodeWork`; the owner's decision, section 9), 8 bytes a step: each row a search of the prefix reads (std's `partition_point` reads at most ⌈log2 n⌉ + 1 of n rows, counted as it reads them), ⌈log2 R⌉ + 1 for a search of the run index, each block a read learns, decodes again or checks for a stored slice, and each run a publish drops. A step the allowance refuses counts nothing and fails the read with `DecodeWork`, the steps before it staying counted; a publish whose steps are refused leaves its run uncached. Tests see the steps through the open's meter (`Meter::decoded`): `tests/bundles/runs.rs` k_reads_over_b_blocks_cost_log_b_steps_each_eagerly_and_lazily (after `load_all`, K reads over B blocks count at most K (2 (⌈log2 B⌉ + 1) + 1) steps, and lazily, last entry first, the blocks once more; the old walk counted none, and a linear search of the prefix counts K x B / 2), rows_over_one_stored_span_check_its_blocks_once, a_read_of_nothing_at_a_blocks_start_reads_no_block; the differential tests `files::bundle::index::tests` (each search of the prefix against a scan of the prefix sums, the run index against a model of every run ever published) and `tests/bundles/runs.rs` random_layouts_read_in_random_orders_are_slices_of_the_joined_data (random layouts with empty, stored, LZ4 and LZMA blocks, random rows read in random orders, lazily, after `load_all` and on four threads at once, against the Python slices of the joined data the builder laid out); the B-tree's charge, `tests/files_peak.rs` publishing_runs_one_at_a_time_holds_nothing_the_meter_has_not_charged. E's perf report is to count re-decoded bytes and the peak of cached runs (R2, R3); it is not yet taken (section 6, "Also measured").
- **Parents.** An entry's `Parent` carries the container's name, kind and nesting depth and, for a bundle, a `Weak` handle on it (the bundle is built with `Arc::new_cyclic`), which `PPtr.deref` scans for siblings (3.13). The meter is not in the `Parent`: `parse_file` is passed it, and each file keeps it (`File::meter()`).

### 3.7 SerializedFile

`files/serialized/` (C) ports `files/SerializedFile.py:206-360` and `files/ObjectReader.py:67-130`. The rules, each with a test:
- **Header** (`SerializedFile.py:255-269`): the four legacy `u32`s big-endian; from 9 the endian byte and 3 reserved bytes at offset 16, below 9 the endian byte at `file_size - metadata_size` (absolute); at 22 the 64-bit fields replace the legacy ones and `unknown` is the trailing `i64`.
- **Gates** (`:271-288`): the version string from 7, the target platform from 8, `enable_type_tree` from 13 (else true), `big_id_enabled` at 7-13 (else 0).
- **Type records** (`:117-148`): `is_stripped_type` from 16; `script_type_index` from 17 (else -1); from 13 `old_type_hash` always and `script_id` only for a ref type with `script_type_index >= 0`, a negative `class_id` below 16, or class 114 (`MonoBehaviour`) from 16; trees only when `enable_type_tree`, in the blob format at 10 and from 12, the old format otherwise; at 21 a ref type reads class, namespace and assembly names and a plain type its dependency list.
- **Objects** (`ObjectReader.py:73-130`): the path id as `i64` under bigID, `i32` below 14, else aligned `i64`; `byte_start` as `u32` (or `i64` from 22) plus `data_offset`, added in `i128` (`ObjectInfo::byte_start`: `2^63 - 1 + 144` loads in UnityPy, and a read from it is a Python slice); below 16 the type is the first record whose `class_id` equals the object's `type_id`, from 16 `types[type_id]` with Python indexing (a negative id counts from the end; out of range fails the file); at 11-16 the object's script index is written back into its type, the last object winning. The `objects` dict keeps a repeated path id at its first position with its last entry: `object_infos()` is file order, `object_order()` is dict order.
- **Script types and externals** with their gates (`temp_empty` from 6; `guid` and `type` from 5; the script identifier `i32` below 14, else aligned `i64`).
- **Eager AssetBundle.** With `ctx.eager_asset_bundle` (UnityPy's default), `parse` reads the container (`container()`, which calls D's `read_container`) of the first AssetBundle in dict order with `check_read`, and a failure fails the file (`SerializedFile.py:316-324`). UnityPy reads that object with `parse_as_object`, object mode (`ObjectReader.py:310-311`): keys are `_clean_name`s and the class is built with an `UnknownObject` fallback (`parse_class`, `UnityPyBoost/TypeTreeHelper.cpp:458-582`), and the container comes from that object. The core reads it in dict mode, so D's fixtures pin that the two modes agree on success, failure and `m_Container` for the trees they can differ on (two names that clean to one key, a tree without `m_Container`, a class that falls back to `UnknownObject`), and any case where they do not becomes a rule here. C's own tests run with it off; D and E test it on.
- **Bounds and strings.** Every table is a `MeteredVec` on the input's meter (3.3), each file charges its own handle (with its resolved version's `heap_bytes`), and every metadata string, the version string a resolved version keeps included, is a zero-copy slice of the file (3.2, 3.4).
- `SerializedType::tree(&Limits)` (scaffold, implemented) compiles the record's `NodeList` with B's `Tree::compile` through `once::get_or_publish`, and the walker reaches a ref type's tree through the `Limits` in its `ReadCtx`, so every reference reuses one compile. `SerializedType::new(class_id, nodes)` and `SerializedType::ref_type(class_id, class, namespace, assembly, nodes)` (scaffold) build records, so B can test R14 and W7 against a ref-type list before C lands.

### 3.8 Typetree nodes

- `typetree/rows.rs` (scaffold): `NodeRow` is one node as stored (`m_Level`, `m_Type`, `m_Name`, `m_ByteSize`, `m_Version`, `m_TypeFlags`, `m_VariableCount`, `m_Index`, `m_MetaFlag`, `m_RefTypeHash`, each `Option` where the format may lack it). `meta_flag` is an `i64`: a blob or old-format tree stores an `i32`, widened with its sign, and a TPK node a `u32` (`Tpk.py:361`), widened without one, so a flag of 2^31 or more is the positive int UnityPy holds (A request 3; G7's synthetic case `meta_flag_u32`). `NodeList::from_rows(MeteredVec<NodeRow>)` is UnityPy's stack rule (`helpers/TypeTreeNode.py:156-188`): a row nests under the nearest earlier row of lower level, so level jumps are kept as UnityPy keeps them; rows after a later top-level row are dropped, but are still processed for errors. It builds its child tables by counting (no allocation per row), each a `MeteredVec` on the rows' meter, and keeps their charges with the rows'. Implemented and tested.
- `typetree/parse.rs` (C): `parse_old(r, data, format, meter, limits)` (`TypeTreeNode.py:78-109`, iterative, `Limits::max_tree_depth`) and `parse_blob(r, data, format, meter, limits, common)` (`:112-154`, `:331-347`), each returning a `MeteredVec<NodeRow>`: `m_Version` is read as `i16` where UnityPy reads it so; a string offset with the high bit set is looked up in `common`, the caller's TPK's table (`ProviderChain::common_strings`), or without one in `COMMON_STRINGS`, and, when absent, becomes its decimal string (`:130`), charged to the meter (`RawStr::charged`, 3.2); a local offset reads to NUL within the buffer, as a zero-copy slice of it. The node area and the string buffer are `reader.read(n)` (`:116-117`), so a negative `node_count` or `stringbuffer_size` is a Python slice that moves the position back (`stream::py_read`, 3.3), not an error. **The rows are a `MeteredVec` on the input's meter**, grown with the rows read, never sized from `node_count`, so a row table whose decoded bytes compress well (a block of repeated rows) stops at the meter's limit (`InputMemory`), not at a row count.
- `typetree/tree/` (B): `Tree::compile(Arc<NodeList>, &Limits)` precomputes per node what UnityPyBoost precomputes (`UnityPyBoost/TypeTreeHelper.cpp:1215-1216`): `Kind` from `m_Type` by exact match (`:1075-1103`) with the `PPtr<` prefix first (`:1105-1128`); `Shape` (what the walker does); `align` (`m_MetaFlag & 0x4000`); `key` (the first sibling with the same name) and `slot` (that key's ordinal among its parent's distinct names), so the dict collapse is O(1); `min_size` (a lower bound on the bytes a successful read consumes, in either reader and whatever registry is in scope, a malformed `pair` or `Array` counting what the pure-Python reader reads of it; it sizes a list's first reservation, `tests/walk_min_size.rs`); `dup_names` and `has_registry` flags. `Shape::Vector` is only for a node whose kind the reader's switch does not handle itself (`Unknown`, `PPtr`, `Array`, `ReferencedObjectData`, `ManagedReferencesRegistry`) and whose first child's kind is `Array` (R9). Malformed shapes compile to `BadPair`/`BadVector` and fail only when UnityPyBoost's reader reaches them (a `pair` run reaches its element once its length is read, even at length 0, R10); the pure-Python reader and the writer read and write a `pair` of three or more children through its first two and an `Array` of three or more through `m_Children[1]` (3.10), so those shapes are not errors there; and a `BadVector` or `BadPair` with fewer children fails in the pure-Python reader only where its own reads reach the missing child, after the length or the first child it reads first (3.10), so `walk/python/` never fails one on entry. `Tree::compile` charges its tables to the list's meter (`TreeError::Charge`); compilation fails otherwise only on depth.

| `tuple` (`pair`; the pure-Python path's aligned primitive arrays) | `Tuple` |
| `dict` | `Dict(Map)`: `(NodeId, Value)` entries in insertion order; `insert` is `PyDict_SetItem` (a repeated key keeps its first position and takes the last value) |

`Parsed { lists, value, bytes_read, charge }` is the self-describing unit, and carries the charge for every allocation its value holds, its `lists` table included (3.15), so a value a caller keeps counts against its input for as long as it lives. **The value cannot leave its charge**: `Parsed::value` is private (`value()` borrows it), and `Parsed`, `Value`, `Map` and `PrimArray` are not `Clone`; `value/mod.rs`'s `compile_fail` doctests pin each, every snippet written so it can fail only one way (it names the missing item bare, or asks for a `Clone` bound), because stable rustdoc does not check a `compile_fail` test's error code. **The reader builds values only through `ValueBuilder`** (scaffold, implemented): `ValueBuilder::new(meter, root)` starts the charged `lists` table; `list_index` adds a ref-type tree's list once per distinct `Arc`; `vec()` gives a `MeteredVec` for a list, map, tuple or run; `list`, `map`, `tuple` and `prims` (over a `PrimRun`, one variant per primitive vector) turn it into a **`Built`, a value that carries the charge for its own heap**, which no public method separates; `scalar` wraps a value that owns no heap (a scalar, a string or bytes sliced from the file, an empty list or map) and hands back a list, map, tuple or run that owns an allocation. It cannot tell a `Str` or `Bytes` that is a slice of a charged buffer (the file's, `RawStr::charged`, a `DecodeBuf::into_bytes`) from one that owns a plain `Vec`, since `bytes::Bytes` does not say, so passing it only the former is the reader's discipline, checked by B's counting-allocator test (`walk_memory::every_allocation_of_a_read_and_a_write_is_charged`), not by the type (round 6). A `Built` goes into its parent's vector through `MeteredVec::push_built` (a list or tuple item), `push_entry` (a dict entry) or `set_entry` (a repeated name's replacement in place), each of which keeps its charge with the parent, or into the `Parsed` through `finish(value, bytes_read)`, which also hands over the lists table's charge. The builder keeps no value's charge, so a value taken out before a builder is dropped (a read that failed half-way) is dropped with its charge, never left uncharged (`value::tests::a_built_value_keeps_its_charge_when_the_builder_is_dropped`; round 5: the builder held every charge until `finish`). `Map` has no growth method outside tests. **`ValueBuilder::finish` is the only way to a `Parsed`** (there is no public constructor; `Parsed::new` and `Parsed::unmetered` are gone, and doctests pin both), so a caller's own value (one to write: the bindings, B's W2 matrix, tests) goes through a builder too, on `Meter::unlimited()` when it is not an input's; `Map::from_entries` builds a map a caller made itself. The types pin that every `Parsed` holds its builder's charge; they cannot pin that every allocation of a value went through the builder, because `Value`'s variants are public data (a value built from a plain `Vec`, or kept after its builder was dropped without `finish`, holds heap no charge covers). That the reader does neither is B's discipline, checked by B's counting-allocator test (7.3). `lists[0]` is the root tree's `NodeList`, and a `ReferencedObject` read through a ref type's tree appends that tree's list **once per distinct tree** (deduplicated by `Arc` pointer, so a list per ref type, not per reference); each `Map` records which list names its keys (`Map::list`, a `ListIx = u32`, tested past `u16`; past `u32` lists `list_index` refuses with `LimitKind::Count`). `bytes_read` is an `i64`: UnityPyBoost's is never negative, the pure-Python reader's is after a negative `TypelessData` length (3.10). `Parsed::field`, `entries` and `get(path)` resolve names. `size_of::<Value>() <= 40` is tested.

**The pure-Python reader** (`walk/python/`, `TypeTreeHelper.py:182-361`) starts at `byte_start` in the whole file, reads with the stream rules of 3.3 at any position, and **aligns relative to the file**, not the object (`align_stream` rounds the absolute position: an object at byte 1 with `[UInt8 a (aligned), UInt8 c]` reads `c` at 4 and 4 bytes where Boost reads it at 5 and 5 bytes). It differs as CANONICAL_DUMP section 7 lists: aligned primitive arrays are tuples with `UInt16`/`SInt16` signedness swapped; an aligned `SInt8` array raises `TypeError` (`other`) at every length, the empty one included, and an array of aligned `TypelessData` raises `TypeError` once it has an element (an empty one is `[]`); a negative or out-of-range string length reads as `""`; in an array whose aligned element is a vector, a negative inner length reads as `[]`, unless the inner element is an aligned primitive, whose `read_*_array` builds a `struct` format from the count and rejects a negative one (`struct.error`, `other`); arrays of aligned class elements align once and skip the registry check; a `TypelessData` length of -1 reads to the end of the file and other negative lengths follow Python slice semantics (so `bytes_read` can be negative, and the dump reports such a read as `other`, as `dump_records.py`'s `error_kind` does: its pattern takes no sign); a read past the end of the file is `other`; and, probed on UnityPy 1.25.2:
- a `pair` with three or more children reads its first two (`:193-196`), where Boost raises;
- an aligned `pair` array reads each child through `FUNCTION_READ_MAP.get(child.m_Type, lambda: read_value(child))` (`:285-293`): a child whose type is in the map (a primitive, a `string`, a `TypelessData`) is read without its own align flag, though a non-empty `string` still aligns itself; any other child (a class, a vector, a `pair`) goes through `read_value` and keeps its flag;
- a primitive node reads through `FUNCTION_READ_MAP`, which holds the base `EndianBinaryReader`'s functions, `unpack(fmt, self.read(n))` (`TypeTreeHelper.py:29-52`, `streams/EndianBinaryReader.py:93-127`), and not the memoryview reader's `unpack_from` (3.3): the position moves by `n` even when it raises, and at position `-n` (`view[-n:0]`, empty) it raises where `unpack_from` reads the last `n` bytes. A length (`reader.read_int()`) and a primitive array (`read_array_struct`, `FUNCTION_READ_MAP_ARRAY`) read with `unpack_from`. `walk.py`'s `py_base_read_*` cases pin both at `-n`, `-n-1` and `-1`;
- a `ReferencedObject` reads `ref_object["type"]` before anything else (a missing key is `KeyError`, `other`), and raises "SerializedFile has no ref_types" for an empty or absent list *before* the empty-class skip (no `ref_types` attribute at all is an `AttributeError`, which the dump maps to `ref_type`), where Boost skips `data`;
- a `ReferencedObject` whose `type` has no `class`, `ns` or `asm` key raises `KeyError`, and one whose `type` is not a dict raises `AttributeError` (`:89-97`), both `other`, where Boost reports `ref_type` (R14);
- a string of length 0, or of a negative or out-of-range length, returns `""` before `align_stream` (`streams/EndianBinaryReader.py:266-273`, the memoryview override), and a `string` node has no align flag of its own, so it does not align: `[UInt8 a][string s][UInt8 c]` at offset 0 with `s` empty reads `c` at byte 5 (6 bytes), where Boost aligns and reads it at byte 8 (9 bytes, R6);
- an `Array` node with three or more children reads its elements through `m_Children[1]` (`:216`, `:309`), where Boost raises "Array node must have 2 children" (R9); the writer writes it the same way (`:434`, 3.11);
- an empty array of malformed `pair`s reads as `[]` (the arity check is inside the loop), except an aligned element of fewer than two children, which raises `IndexError` (`other`) at every length, the empty one included (`read_value_array`'s aligned path takes `m_Children[0]` and `[1]` before the loop, `TypeTreeHelper.py:282-283`);
- likewise an array whose aligned element is a vector whose `Array` has fewer than two children raises `IndexError` (`other`) at every length, the empty one included (`subtype = node.m_Children[0].m_Children[1]` before the loop, `:309`), where Boost reads an empty one as `[]` (R11 reads elements one by one); a non-aligned one, or one whose `Array` has three or more children, reads an empty array as `[]`. **The general rule:** `read_value_array` reads an aligned element's `pair` children (`:282-283`) and its vector's `Array` element (`:309`) before its loop, and indexes everywhere else inside it, so a malformed shape of those two kinds fails at length 0 and any other fails only once an element is read; `tools/fixtures/pure_python_rules.py` runs every item of this paragraph that concerns an empty array or a `pair` child against both readers (section 10);
- **outside an array, the order of reads decides the error**: a vector reads its length, and refuses a negative one, before it indexes its `Array`'s element (`size = reader.read_int()`, "Negative length", then `m_Children[0].m_Children[1]`, `TypeTreeHelper.py:213-216`), and a `pair` reads its first child before it indexes its second (`:194-195`), so a vector whose `Array` has fewer than two children is `negative_length` at length -1 and `IndexError` (`other`) at length 0, and a `pair` of one child fails with its first child's error (`negative_length` for a vector of length -1), where Boost checks each arity first (`TypeTreeHelper.cpp:820-833`, `:328-332`) and reports `other` (`tools/fixtures/pure_python_rules.py`'s last five cases, round 5);
- an aligned `ReferencedObject` array element whose class is empty or whose ref type has no tree raises (`read_value(None, …)`, `ReadDetail::RefTypeNoTree`, kind `other`); everywhere else both readers skip `data`.

**Floats.** `FloatMode::UnityPy` (default) quiets an f32 sNaN as above; `Lossless` keeps the bits. `F64` keeps every bit in both modes.

**Linear dicts.** A class whose children repeat a name (`dup_names`) is the one place a read could go quadratic: `Map::insert` scans, so a hostile tree with *n* children and late repeats would cost *n*² per object. The walker never calls `insert` per child. It keeps a per-class scratch from `slot` to entry position (cleared per class read, so a registry child skipped at run time, R13, cannot misplace a later key): a first sighting pushes, a repeat overwrites in place with `Map::replace_at`. The dict keeps first position and last value, as `PyDict_SetItem`. Sizing the dict is not linear in the children read: a class whose children repeat a name or hold a registry, and every `ReferencedObject`, pass over all of their children before the first is read (to count the dict's entries, find `type`'s slot, clear the slots), so a read that fails at the first child had done work in proportion to all of them, and K objects over one class of *k* children, each failing at its first child, cost K·*k* steps nothing counted (review round 6: 65,536 objects over 2^20 children). Each step of those passes now counts as the open's work before it is taken ("Work per open"), and every other class, the common case, reserves one entry a child and makes no pass (`walk::prepass_tests` counts the steps; `tests/walk_prepass.rs` stops K reads over a class that repeats a name at the open's allowance).

**Linear references.** A `ReferencedObject` finds its ref type as UnityPy does, by the first `(class, ns, asm)` match in the file's list, but a hostile object of *n* references into *n* ref types would cost *n*² comparisons that way (review round 2). Each read and each write scans as UnityPy does until its scans have passed the list's length; then, for a list longer than eight, it builds a table from each `(class, ns, asm)` to its first index, once, charged before it allocates, and probes it (`walk::dict::RefIndex`): at most twice UnityPy's own scans, and at most three steps a ref type plus eight a reference (a comparison or a probe hashes only bytes the read has read, or the write writes). Each `type` value is resolved once for all its `ReferencedObjectData` children, and the value's table of node lists finds a ref type's list by its address past eight lists (`ValueBuilder`). The list is not indexed across a file's objects: each object's read consults it again, as UnityPy's does. A tree's compile groups a class's children by name in `O(k log k)` comparisons, colliding hashes included. `walk::linear_tests` counts the steps (never time) of *n* references into *n* ref types, of *d* data children of one `type`, and of *k* same-named siblings over one `ReferencedObject`, in both readers and under both writer rules, each at most 32 a reference or 16 a child and entry.

**Bounds.** Every list, map, tuple and primitive run a read builds is a `MeteredVec` on `ReadCtx::meter` (the input's), so its capacity, spare or not, is charged before it is allocated; the reader hands each one's charge to the `Parsed` through `ValueBuilder` (3.9), and a refused charge is `ReadDetail::Charge` (kind `other`). To hold no spare capacity, a list first reserves `min(len, remaining / min_size, Limits::max_prealloc)` and then grows by `reserve_exact` in steps of at most `max_prealloc`, never past `len`, and a dict is sized from the compiled tree, its class's distinct child names, so neither holds more than its final length after the read (a `ReferencedObject`'s dict reserves all but its data's names, which a read may skip, and a data child it reads grows it geometrically, never past its distinct names: review round 6's sweep found it growing by one entry at a time, so a growth that moved it copied every entry before, which only the allocator's growing it in place kept linear). `max_values_per_object` bounds the work of one read (every `Value` built, the elements of a primitive run included: the pure-Python reader can read the same bytes again after a negative length; and every child the read skips, a `ReferencedObject`'s data that resolves to no tree or a registry once one is in scope, since a class's loop visits it whether or not a value comes out: review round 3, *n* elements of *k* skipped children each cost *n*·*k* while the values stayed under the bound; `walk::linear_tests` counts the loops' turns, never time, at most twice the bound once it refuses); nesting (ReferencedObject data re-enters trees) counts against `max_value_depth`: UnityPyBoost's reader counts each level it recurses through, and the pure-Python reader each frame Python would count (each `read_value` and `read_value_array` call, each list or dict comprehension and `lambda` they run), so a value Python refuses with `RecursionError` is refused first, and `Limits::stack_needed` is the stack the bound costs (`tests/walk_stack.rs` reads and writes the deepest value of every shape `tests/fixtures/walk/depth.json` records on a thread that size, and measures what each needs); an array element whose read ends no further on than it began (it read nothing, or the pure-Python reader's negative `TypelessData` length took it back) counts against `max_zero_size_elements`: what the element really read, not its tree's `min_size`, since which children a read skips depends on the registry in scope and the pure-Python reader reads a malformed `pair` or `Array` (review round 4: both were refused past the bound where UnityPy read them; `tests/walk_elements.rs` replays UnityPy's reads of 2^20 + 1 elements). **Work per open.** These bound one read; every read and every write also counts its work toward its open's `max_decode_work` (3.6, "Decode work"), whatever its outcome: `walk::VALUE_WORK`, the size of a `Value`, for each value it builds, writes or skips, and for each element of a primitive run a read holds as a run, or each primitive a write writes, its bytes; each byte of a string a write copies, or passes over to find its characters (a `pair` or an array sibling a repeated name hands a string); `walk::STEP_WORK` (8) for each step that builds no value: a step of a pass that sizes a dict or clears its slots, an entry a lookup by name passes, a name a writer's table indexes or probes, with the bytes of a name it compares or hashes; and for each ref type its lookups compare or index, and each probe of their table, `walk::VALUE_WORK` and the name bytes it reads. A step is counted before it is taken, on the read's or the write's `walk::OpenWork`, which adds the steps to the open's meter a chunk at a time (`walk::WORK_CHUNK`, 64 KiB) in one atomic check-and-add: a chunk that would take the open past its allowance is refused and the read or the write fails (`limit DecodeWork`, a read's kind `other`), the steps before it counted; one whose own work, counted when it ends, took the open past its allowance fails too, its own failure first if it has one. So the reads and writes that succeed never do more work together than the allowance, on any number of threads, and each one in progress does at most a chunk and a step past it before it stops (review round 6: a read added its work only when it ended, so two reads on two threads both passed the start's check and ran to their end past the allowance). Once the open's work has passed its allowance, a read or a write is refused before it starts. Objects may share their bytes, and a read refused by its own bound keeps nothing, so K objects over one span repeated it K times with no bound on the input (fix pass 4's sweep: a vector of 2^22 empty structs, refused after 2^20, read by every object of a small file); and the ref-type index is one read's or write's, so K objects over R ref types searched the list K times, K x R steps no value counted (fix pass 5's sweep) (`tests/walk_work.rs` objects_over_one_span_stop_at_the_opens_work, objects_over_many_ref_types_stop_at_the_opens_work, a_read_and_a_write_count_their_work_on_the_open, a_lookup_counts_the_ref_types_it_reads, a_refused_read_or_write_counts_what_it_did, past_the_opens_work_a_read_or_a_write_is_refused, two_reads_or_writes_on_one_meter_pass_its_allowance_once; `tests/walk_prepass.rs`; `walk::write::work_tests`).

### 3.11 Writing

`walk/write/` (B) ports UnityPy's `write_typetree` (`TypeTreeHelper.py:161-179`, `:381-458`) under `WriteRules::UnityPy`:
- W1 dispatch on the type name first, then `pair`, `ReferencedObject`, an `Array` first child, then a class;
- W2 **duck typing**: the writer takes any value Python's operations accept, not only the variant the reader makes for the node, which a duplicate-name object exercises (its dict holds one child's value under the other's node). Probed on UnityPy 1.25.2, per node kind: a `bool` node takes any value (`struct.pack('?')` uses truthiness; an empty `Str`, `Bytes`, `List`, `Tuple` or `Dict` is false); an integer node takes `Bool` and `Int`/`UInt` in range (a float, or an out-of-range int, is an error); a `float` or `double` node takes `Bool`, integers and floats (a finite float that overflows `f32` is an error); a `string` node only `Str`; `TypelessData` only `Bytes`; a `pair` node anything with items 0 and 1 (`List`, `Tuple`, `Prims` or `Bytes` of length 2 or more, a `Str` of 2 or more characters), each item written through its child's kind; an array any sized iterable (`List`, `Tuple`, `Prims`, `Bytes` as integers, `Str` as one-character strings, a `Dict` as its keys), each element under the same rules; a class with no children takes any value and writes nothing (its non-dict branch iterates no children); a class with children takes a `Dict` (`value[child.m_Name]`, W6) or any other value that has each child's cleaned name as a Python attribute (`getattr(value, child._clean_name)`, `TypeTreeHelper.py:447-455`: an `int` value satisfies a child named `real`, a `list` one named `count`, whose bound method a `bool` node writes as true), and B's fixtures record which attributes each `Value` variant's Python type has for the names its matrix uses;
- W3 strings always align;
- W4 `TypelessData` writes its length and bytes and aligns only when flagged;
- W5 arrays write the length, then each element, and **each element aligns when its node is flagged** (`:435`), then the vector or `Array` flag aligns once: the writer does not mirror the reader; an `Array` of three or more children writes its elements through `m_Children[1]` (`:434`), as the pure-Python reader reads them;
- W6 a class writes `value[child.m_Name]` for every child: a missing key is `MissingKey`, an extra key is ignored, registry scope as on read;
- W7 `ReferencedObject` data needs non-empty ref types (`:99-100`, where the reader does not raise) and a ref type with a tree: an empty class, or a matched ref type with no tree, fails (`KeyError: 'data'` on the value the reader made, which left `data` out; an `AttributeError` on the `None` node when the value has one).

The writer's output is a `DecodeBuf` on the object's meter (`walk::write`, `WriteError::Charge`), so a write is charged like a read. Finding each child's entry, `value[child.m_Name]` (W6, W7), takes steps linear in the children, as a Python dict lookup does (`write::Lookup`): a cursor walks the entries in step with the children; a dict the reader made through the node being written also keeps a per-node table from slot to entry position (a `MeteredVec<u32>`, one `u32` per distinct name) for a name an earlier child took; any other miss (a dict keyed by another node's children, as a repeated name hands a same-named sibling) finds the name in a table from each name to its first entry, built once per dict on its first miss. Each step of it that builds no value is the open's work, counted before it is taken (3.10, "Work per open"): the passes that count and clear a node's slot table (only a node whose children repeat a name keeps one, so any other makes no pass), a name compared off the node's own children, and a name a table indexes or probes, each with its bytes. A repeated name hands its one dict to every same-named child, each of which writes it whole, so inside a class whose children repeat a name every such table is kept by the dict's address until the outermost such class is written (`write::KeptTables`): a dict, and every dict inside it, is indexed once however many siblings write it (review round 2: *k* siblings over a dict of *k* entries cost *k*²). A `ReferencedObject`'s ref type is resolved once a write of its dict (3.10). These tables are the writer's only allocations besides its output, charged to the meter of the value being written (`Parsed::charge().meter()`), since `WriteCtx` has no meter of its own, the name table at `limits::HASH_TABLE_SHARES` buckets a name; `tests/walk_memory.rs` checks they are charged before they are allocated (B request 6), and `write::tests` counts the steps of a `ReferencedObject` of 2^16 children and of a class of 2^16 children written from a dict keyed in the reverse order (at most 2 and 4 a child), and of 4,096 same-named siblings over one dict of 4,096 entries, and over a dict inside it (at most 4 a sibling and entry).

The writer counts the frames UnityPy's `write_value` runs, one a call and one more for an array's list comprehension (`:435`), against `max_value_depth`, and refuses past it (`WriteError::Limit`, `ValueDepth`): every value UnityPy's writer raises `RecursionError` on, unityrs refuses too (`PARITY.md` section 19.3). It counts every value it writes (each `write_value` call) and every child it skips (a registry in scope; under `MirrorReader`, data the reader skipped) against `max_values_per_object`, the bound the read counts against, and refuses past it (`WriteError::Limit`, `ValuesPerObject`): a tree that repeats a name hands one value to every child of the name, which writes it whole, so *k* such children write a value of *n* elements *k*·*n* times, which no output bound stops when the children's nodes write nothing (review round 3: `vector<Empty>` siblings over one `vector<int>`). A write through the tree its value was read with, one that repeats no name, counts no more than its read did, so the bound refuses no write whose read it allowed (`tests/walk_bounds.rs`, over every recorded case and both rules); where a repeated name makes a write count more, UnityPy writes it and unityrs may refuse (`PARITY.md` section 19.3).

W2 does not model Python's dunder attributes: a class written from a non-dict value, one of whose children cleans to a dunder name (`__class__`, `__doc__`, `__len__`, …), is `WriteError::TypeMismatch`, where UnityPy's `getattr(value, child._clean_name)` (`TypeTreeHelper.py:447-455`) finds whatever that object has (a type, a method wrapper, a `str`) and writes or rejects it by the child's kind. Only a hostile tree reaches it (a class node over a non-dict value, a dunder node name); `PARITY.md` lists it (E, B request 4).

`WriteRules::MirrorReader` aligns once after a primitive or pair run and writes an empty-class `ReferencedObject` without `data`, as UnityPyBoost reads them, so a value UnityPyBoost reads through a tree that repeats no name writes back to bytes that read as the same value and the same `bytes_read` (`walk_fixtures.rs` mirror_reader_round_trips_what_the_reader_reads; padding is written as zeros, whatever the file held). A class whose children repeat a name keeps only the last one's value (`PyDict_SetItem`), so no writer can give back the bytes of the others (`tools/fixtures/walk.py`'s case `r12_duplicate_after_vector`: UnityPy writes its first `x`, read as 1, as the last one's 3). It is opt-in (`PARITY.md`, Tier C).

### 3.12 Providers and objects

- **Tree resolution** (`ObjectReader.py:285-307`), `ObjectRef::tree(nodes)` (D): an explicit `nodes=` tree; else the type record's own tree (`TreeSource::Embedded`); else `ctx.providers.lookup(TreeRequest { class_id, version, script: None })` (`TreeSource::Provider(name)`); else `Ok(None)`, which reads as `ParseError::NoTypeTree`.
- **The `MonoBehaviour` script hook** needs an Environment, so it is `Environment::object_tree(obj, nodes)` (D), not `ObjectRef::tree`: when the tree came from the provider chain (not an explicit `nodes=` tree and not the type record's own: UnityPy calls `generate_monobehaviour_node` only inside `if not node:`, `ObjectReader.py:296-304`), its root type is `MonoBehaviour`, and a provider in the chain accepts script requests (`TypeTreeProvider::accepts_scripts`, UnityPy's `env.typetree_generator`), the head is read with that tree (`check_read` off), `m_Script` is dereferenced through the Environment and parsed, and the provider is asked with its `ScriptIdent`. As in UnityPy (`ObjectReader.py:332-346`), only a `ValueError` there falls back to the class tree (a null `m_Script`, a value error in the head read, the provider's miss); a dereference failure (`FileNotFoundError`, `KeyError`, `IndexError`) is the object's error. With no such provider nothing is dereferenced (UnityPy raises its `ValueError` before any deref), so in P1, where no provider accepts scripts, `object_tree` equals `ObjectRef::tree`.
- **`ProviderChain`** (`provider.rs`, scaffold, implemented) asks providers in order, first answer wins, under `(class_id, packed version, script)`: UnityPy's `CLASSES_CACHE` key (`helpers/Tpk.py:16`, `:44`), where rabex keys by class alone and so answers every later version with the first version's tree (`docs/spikes/rabex.md` section 5). It caches **answers only**, as UnityPy does (`get_typetree_node`, `Tpk.py:42-55`, raises on a miss before `CLASSES_CACHE[key] = node` at `:54`), so a miss under an input-chosen key leaves nothing behind. The cache is bounded per chain (`ProviderChain::DEFAULT_CACHE_ENTRIES`, 65,536 entries, and `DEFAULT_CACHE_BYTES`, 64 MiB of slots and keys; `with_cache_bound` sets others): past the bound an answer is returned and not kept. A lookup searches the cache through a borrowed view of the request and copies nothing. Whether an answer is kept is decided from that borrowed view too (already cached, the cache full, the entry's cost over the byte bound), and only an answer that is kept copies the request's strings into its key, so a hit allocates nothing, a key the cache will not keep (too big, or any key once the cache is full) is never copied, a cached key holds no input's buffer, and the copy counts toward the chain's 64 MiB (`provider::tests::a_lookup_copies_nothing_but_the_key_it_keeps`, `a_key_the_cache_will_not_keep_is_never_copied`). An entry counts four buckets of the table (`limits::HASH_TABLE_SHARES`: a doubling table holds up to 16/7 buckets per key at rest and 24/7 while the old and the doubled table are both live) plus its key's heap at `heap_cost` (`the_byte_bound_covers_the_table_at_rest_and_while_it_doubles`). Providers are called with no lock held, so a provider may call the chain.
- **Providers share their trees.** A provider answers every request that maps to one tree of its data with one `Arc<Tree>`. UnityPy's `NODES_CACHE` holds one node tree per distinct TPK class record (`generate_node`, `Tpk.py:58-88`; `TpkUnityClass` hashes by value, `:316-330`), shared across versions and classes; the TPK provider holds one per release root, the only field of the record the walk reads, so it shares a tree wherever UnityPy does, and between equal roots of unequal records too. So the trees a chain's cache points at are bounded by the provider's data, not by how many versions an input names, and they belong to the provider, not to an input's meter (3.15's constant); the TPK provider bounds them in total (below).
- **`unityrs-tpk`** (A): a port of UnityPy's `helpers/Tpk.py` on raw bytes. `TpkProvider::open(path)` reads the TPK as `TpkFile` and `TpkTypeTreeBlob` read it (the payload decoded with core's codecs), picks a class's entry for a version as `get_item_for_version` does, by core's `UnityVersion` ordering (UnityPy's), walks the node buffer from the entry's release root into `NodeRow`s as `generate_node` does, and compiles each release root's rows once with `Tree::compile` on the provider's own unlimited meter and keeps them (every request whose entry names one root gets the same `Arc`). Every bound is checked before what it bounds is allocated: the file, the decoded payload, each table of the blob, a tree's depth and rows, and the rows every root's walk builds together, kept or not (`TpkProvider::MAX_TOTAL_ROWS`: a walk that fails counts the most rows it builds before it fails, so the bound limits what the provider keeps and its work on any one thread; threads that ask for one root before its first answer is published each walk it once, the price 3.16 states for never waiting, so T threads asking at once build at most T times the bound; a walk the allocator refused is the exception, not kept (3.1's transient rule), so each later request for its root walks it again, each walk bounded at one row past `MAX_TREE_ROWS`; decided at load in the order of the roots' ids, so a refusal never depends on the order of the requests; `PARITY.md` section 19.3). It answers `Ok(None)` wherever UnityPy builds no node list (`unitypy_dump.py` records each as `no_typetree`): a class the TPK does not hold (`KeyError`); a version below the class's first entry, or a picked entry that is `None`, the class removed at that version (`ValueError`, `Tpk.py:472-481`); a picked entry with no release root (`AssertionError`, `Tpk.py:64`). **The pick is UnityPy's floor over every entry** in its stored order (`get_item_for_version`: the last entry whose version is at or below the request, stopping at the first above it), `None` and release-less entries included, so the provider never steps back past one of them to an earlier entry that has a tree (the trait's doc says so, `provider.rs`). Its `name()` is `"tpk"`.
- **`ObjectRef`** (D; the handle and its getters are the scaffold's): the file's `Arc` and the row's index (3.1); `raw_data()` (zero-copy, cut at the end of the file), `read_typetree(nodes, check_read)`, `parse_as_dict(check_read)`, `write_typetree(value, nodes, rules)`.

### 3.13 The Environment

`env/` (D) ports `environment.py:27-363`, `classes/PPtr.py:43-90` and `helpers/ResourceReader.py:10-38`.
- **Registry** (`env/registry/`): keys are `simplify_name(name)`; dict semantics (a repeated key keeps its first position and takes the new value); every `SerializedFile` and raw entry of a bundle is registered by its entry name **as it is parsed** (`files/File.py:76-90`), and every file loaded at top level by its name (`environment.py:154-157`). **Partial registration:** under `Eager`, a bundle whose entry fails to parse fails `load_file`, which raises before the bundle enters `files`, but the CABs of the entries parsed before it stay registered and resolvable (probed on UnityPy 1.25.2 with a bundle `[good CAB, its .resS, bad CAB]`: `env.files` is empty, `env.cabs` holds the first two). Under `LoadMode::Lazy` a bundle registers every directory entry's name at open, in directory order (a repeated path keeps its first position and its last entry, as the eager dict does), and parses an entry on first `get` (computed with no lock held, then published, 3.16). **What a slot holds:** a file the caller loaded is never evicted, so its slot may hold its handle; a dependency's slot never holds a strong handle on it, only what reopens it (its name, its `Source`, its meter, and the path of directory indexes from its top-level file to the CAB: empty for the file itself, `[i]` for entry `i`, `[i, j]` for entry `j` of the bundle that is entry `i`) and a `Weak` on the handle the dependency LRU keeps, so evicting the dependency frees it, its nested bundles included (below). A CAB inside a dependency's nested bundle is reached by walking `entry()` along its path from the LRU's handle, never through a handle on the nested bundle, which would keep it (and the slice of the outer's decoded run it is made from) alive past the eviction. **Ranks** (review round 1): each registration has a rank, the sequence number of the load that made it and then its path of directory indexes, and a key's position is its least rank and its value the registration of greatest rank, which is the eager dict's order and value whatever order the registrations arrive in (`env/registry/mod.rs`'s module docs); the `order` index is a B-tree keyed by rank. Every registration is charged to the meter of the input its slot belongs to (a dependency's slots to the dependency's own meter, whichever handle read the entry: 3.16, R2): the key (`RawStr::charged`), the slot's `Arc` and its rank's path, an element of the `order` B-tree (a fifth of a leaf and a thirtieth of an internal node, which std's minimum occupancy covers; the first key also pays for the root leaf) and four buckets of the `slots` hash table: a doubling hash table holds up to 16/7 buckets per key at rest and 24/7 while it grows (`limits::HASH_TABLE_SHARES`, which the provider cache's bound uses too), so the tables' spare capacity and every growth are paid for, and only each table's fixed part (the hash table's 16-byte control tail and the allocator's rounding) is left, a constant per registry (3.15). A `Lazy` load's slot also pays for its place in the lists of dropped slots waiting to be reached (`env/registry/pending.rs`: two B-trees, the slot's share of a node as a key's of `order`); each list's root, one node at most, and none once the list empties, is part of that fixed part.
- **Load modes.** `Eager` is UnityPy (`load_all` at load); `Lazy` is the batch engine's. They give identical results for every read on a scene whose blocks all decode, whose entries all parse and none of which is itself a container. Everywhere else the differences are exactly these, and a test pins each: (a) **failures move**: an entry that fails to parse (or whose AssetBundle read fails) fails the whole bundle at load under `Eager` (with the partial registration above), and under `Lazy` fails only the `get` that parses it, so a sibling stays readable and an entry shadowed by a later one of the same path is never parsed (only its first 21 bytes are read, to tell a nested container, (b)); `BundleFile::load_all` under `Lazy` returns exactly `Eager`'s error; (b) **nested containers**: an entry that is itself a bundle is not a CAB under `Eager`, which registers its entries in place; `Lazy` cannot know that without decoding it, so the entry is registered under its own name, a key whose slot answers `None` (`Eager` has no such key, and keeps an earlier directory entry of the same path under it when that was a CAB), until it is *reached*: its first 21 bytes are read and, when they are a bundle's, it is parsed and its whole subtree registered at the ranks `Eager` gives it (a container inside it has no key), whichever container was reached first and from whichever thread, all of it before the call that reaches it returns. **The invariant `Lazy` keeps:** one routine (`Registry::reach`) reaches a nested container before any of these returns: a lookup that resolves its slot (a `get` of its name, a pointer that names it); a lookup from a file inside it (a dereference, a resource read: the container below the file's top-level bundle, through the file's own handle); a pointer or a resource candidate that reaches it through the asking file's own bundle; a container pass, which reaches every registered entry before it walks; and a registration that drops its slot unreached (replaces it, or ranks below its value), which reaches the dropped slot (`Registry::settle`), since nothing could reach it by name afterwards. So every lookup on a path through the container answers as under `Eager`, and what remains of (b) is the container's own key and a lookup by name alone (`get_cab`, `find_file`, a pointer to a file that is not the asking file's sibling) of an entry of a container nothing has reached, which misses or finds an earlier registration of its key. Two drops are not reached at the drop (section 9, Q13 and Q14, decided 2026-10-30 and revised after review round 6). A slot of a dependency the LRU evicted is not reopened by a load's or a lookup's `settle` (the batch pool; under `EnvOptions::unitypy()` nothing is evicted): it waits on a list of its own for the container pass, which opens the dependency again and reaches it, so the pass walks every table an eager load registered and every `container_path` is `Eager`'s (review round 6: nothing reached it, and the paths its tables set in other files were missing); until a pass, a lookup by name alone of an entry of its container misses, as above. A slot of the same entry of the same input (a reload of the file on the same `Bytes`, which every handle on the dropped entry can tell without reading, `registry::entry_of`) is not reached at the drop: the reload's slot stands in for it, a lookup from a file inside the earlier load's container reaches the standing slot through the reload's handle, and the standing slot's reach registers the entries at the dropped slot's positions with the reload's values, as `Eager` registers both loads, in one parse (review round 5: nothing reached the standing slot from the earlier load's files, and their resource reads missed; review round 6: the entries took the reload's positions, so the container listed its rows in another order and `container_path` gave an object another row's path). A reload no handle can tell is the same input (two `Source::Path` loads of one path) is an ordinary drop, reached. A refusal while reaching a dropped slot keeps it listed, and every reader retries it (3.16, R3: every load's registration, lookup by name, key listing and container pass settles first; the pass fails with it); a refusal by the input's own meter counts as that open's work, so past its allowance the reach is refused with `DecodeWork` and kept (R5). `tests/env_fixtures.rs` `lazy::lazy_answers_every_lookup_as_eager_does` runs every lookup alone after each testkit scene's loads, in both modes under both option sets, and `evicted::dependency_scenes_answer_as_unitypy_whatever_the_pool_evicts` the dependency scenes under a pool that evicts every dependency, and they assert exactly this (review rounds 1, 3 and 4: entries went to the end of the order; a second thread found a container marked expanded with none of its entries; a read from inside a nested container, a container a later load's entry dropped unread, and a pass that had walked a key's value a later container replaced each missed what `Eager` gives); (c) **block failures**: a block that fails to decode, or trips a limit, after the last byte any read needs fails the load under `Eager` (UnityPy decodes every block before any entry, `files/BundleFile.py:173-186`) and nothing under `Lazy`; (d) **overlapping spans**: under `Lazy` each read whose span no cached run covers decodes its whole span again and keeps it (3.6), so a directory of nested or overlapping spans can charge the meter past its limit (`InputMemory`) where `Eager`'s one run fits; read in directory order, a bundle whose entries do not overlap holds at most `Eager`'s run plus, a second time, each block that straddles an entry boundary. Each of (a) to (d) is a row of `PARITY.md` section 19.3 (`Lazy` is `batch()`'s mode). Opening a bundle `Lazy` therefore reads its header, blocks-info and directory only (4.1). The container pass is the same in both modes: a pass whose own loads register a new key raises UnityPy's `RuntimeError` under either (review round 1: `Lazy` never raised it), and a nested container's entries registered under `Lazy` are not new keys. A test runs every Environment scene in both modes and compares, asserting identity on the well-formed scenes and exactly (a), (b), (c) and (d) on the others; G5 also compares `Eager` with UnityPy on every scene (section 6).
- **`find_file`** (`environment.py:310-354`): `get_cab`, else the `CabResolver` (UnityPy walks `env.path`; the core never opens a path it was not given), loading what it returns as a dependency (`load_file(fp, name=name, is_dependency=True)`, `:332`, `:354`). UnityPy's own walk finds only an exact file name on a case-sensitive file system: it keys `local_files_simple` by a lower-cased path, which the open then misses unless that path exists, and `find_sensitive_path` never matches a name without a directory; the resolver is the caller's, so the core has nothing to mirror (D request 6).
- **Names.** UnityPy's `File.name` is a basename (`files/File.py:38`: a loose file loaded as `a/CAB-A` is named `CAB-A`, a resolver load keyed `<env.path>/cab-loose` is `cab-loose`); the core keeps the whole name, which `files()` keys need, and a binding or dump that prints UnityPy's `name` takes the part after the last `/` (D request 6).
- **Resolver loads are files** (probed on UnityPy 1.25.2: two copies of one bundle in a temporary `env.path` beside a loaded bundle, `env.files`, `env.objects` and the container rows printed after each step). `load_file` always records what it loads in `env.files` (`environment.py:159`), and keys a path by the path itself (`:118`), so: **a resource fallback's loads** (`SerializedFile.load_dependencies`, `SerializedFile.py:339-349`: the file's externals and the four candidates, through `load_file(name, True)`, whose second positional parameter is `parent`) are **not** dependencies: each enters `env.files` under the name asked, its objects join `env.objects` and its CABs' rows join `env.container`, and a second fallback parses the file again and replaces the entry in place (dict semantics); `load_file` parses the file with the Environment as its container whatever `parent` it is given (`environment.py:107-108`, `:154`), so a pointer with `m_FileID > 0` from such a file's object resolves as a top-level file's does, in UnityPy as in the core (the testkit scene `fallback_file_pointer`, recorded by `tools/fixtures/env.py`; review round 1 ran UnityPy 1.25.2 and refuted this plan's earlier claim of an `AttributeError`); **`find_file`'s load** is a dependency, keyed by the joined path `env.path/name`, which `env.objects` (it walks `env.files`, skipping a dependency) and `env.container` (it walks `env.cabs`, skipping a dependency) leave out; its CABs replace same-key CABs in `env.cabs`, so a replaced non-dependency file's rows leave `env.container` while its objects stay in `env.objects`. **The port does exactly that under `EnvOptions::keep_resolver_loads`** (true in `EnvOptions::unitypy()`): `Environment::files()` lists, as an iterator (`FileEntries`, which copies nothing), a `FileEntry { name, file, is_dependency }` for every caller load and every resolver load, a fallback's under the name asked with `is_dependency` false (registered as a caller load: a slot holding its handle), `find_file`'s under the resolved source's name (a `Source::Path`'s path, as UnityPy keys the joined path) with `is_dependency` true (its registry slot a dependency's), none of them evicted, each entry charged to its file's meter (its key and its share of the list, as a registry slot's are, since the input chooses how many); `objects()` walks `files()` and skips dependencies, `container()` walks the registry and skips dependency slots, as UnityPy does. With `keep_resolver_loads` false (`EnvOptions::batch()`), every resolver load is an LRU dependency (below), evictable, and in neither `files()`, `objects()` nor `container()`: a `PARITY.md` divergence (E lists it), which G5 does not meet, since G5 compares `Eager` under `unitypy()` options.
- **`deref`** follows `PPtr.py` in order (`env/pptr.rs` lists the rules): `m_PathID == 0` raises; `m_FileID == 0` is the own file; else `externals[m_FileID - 1]` by `pptr::external_index` (scaffold, implemented, pinned by `tests/fixtures/scaffold/pptr_external.json`): computed in `i64` (`i32::MIN - 1` must not wrap), the guard is only `>= len` (`FileNotFoundError`, `DerefError::FileIdPastEnd`), and then Python indexing, so a negative id counts from the end and one below `-len` is `IndexError` (`DerefError::FileIdBelowStart`). The container preload (`helpers/ContainerHelper.py:43-46`, `except (FileNotFoundError, KeyError): continue`) skips `FileIdPastEnd`, `NotFound` and `MissingObject`, and propagates `FileIdBelowStart` (`IndexError`), `RawTarget` (`AttributeError`), `Null` (never reached: the preload skips null pointers first) and `Load`: a load's failure as that load's error, any other as `Error::Deref(Box<DerefError>)`; the `MonoBehaviour` script hook's failures (every one but `Null`, which falls back) are `ParseError::Deref` (D request 3). **The file's container** is its bundle for a bundle entry, and for a file loaded at top level the Environment that loaded it (`environment.py:154` passes `self` as the parent, `files/File.py:36`): UnityPy's "no container is set" is raised only for a `SerializedFile` built outside any Environment, which `Environment::deref` never sees, so the core has no such refusal (probe: two loose files `a/CAB-A` and `b/CAB-B`, A's external `archive:/CAB-B/CAB-B`, resolve to B's object in UnityPy 1.25.2; the testkit scene `loose_external_pointer` asserts it). The cleaned external path is compared with each key of the container's `files` lower-cased (no basename), then `find_file`; a raw target, or a container under an Environment `files` key, has no objects; a missing path id is a `KeyError`. Each outcome is a `DerefError` variant. `from` need not have been loaded into this Environment (a second handle a caller opened on the same bytes): its bundle siblings come through its `Parent`'s weak bundle handle (3.6), every other CAB from the Environment. **When that bundle has been dropped** (a caller kept an `ObjectRef` and dropped its bundle, which UnityPy cannot do: its `assets_file.parent` is strong), a pointer that needs the container fails with `DerefError::ContainerDropped { name }`; the core does not guess between "no sibling" and `find_file`, which could answer with another file of the same name. A caller that hands out files (the bindings, a batch engine) keeps a strong bundle handle beside each `SerializedFile` it hands out, so it never sees this: `Environment::get_cab_held` returns a dependency's CAB with its top-level file (`HeldCab`), and the container pass holds the same handle while it walks a dependency's table (review round 1: an eviction the walk made failed `container()` with `ContainerDropped`).
- **Resources**: the four candidates (`basename`, `name.resource`, `name.assets.resS`, `name.resS`), each a slice of the object's path and a static suffix (`resource_candidates(&RawStr) -> [Candidate; 4]`, no copy; the whole name and its lowered key are built, charged to `from`'s meter, only while one lookup runs), `get_cab` each, then load the file's externals and the candidates through the resolver and try again (each load recorded as the bullet above says: a non-dependency file under `keep_resolver_loads`, an LRU dependency without it), then `NotFound::Resource`. The CAB is resolved by that rule, but each candidate's slot is first **located without being parsed**. When the core can tell **without reading anything** that the slot is an entry of `from`'s own input, the entry is read through `from`'s bundle (its `Parent`) and the shared slot is never parsed, so neither resolving nor reading decodes anything through another handle or charges its meter or pool: the slot's open handle is `from`'s bundle itself, or the slot is a `Source::Bytes` dependency whose `Bytes` are `from`'s bundle's source (the same allocation and range, `BundleFile::source`) at the entry's directory index. A `Source::Path` or `Source::Fetch` slot whose handle was evicted holds only a path or a fetcher, so telling would mean reopening it, which is the charge the redirect exists to avoid; such a slot resolves by UnityPy's rule, through the slot, on its own meter and pool. The bytes are the same entry's either way, so neither path changes an answer. So no `Source` gets both the redirect and the freeing of its bytes on eviction (below) for a job's second handle: `Bytes` keeps the redirect and its bytes, `Path`/`Fetch` frees its bytes and loses the redirect once evicted. Which one a batch engine's inputs get, or whether its jobs read through the handle `load_dependency` returned (whose identity the redirect sees whatever the source), is the batch plan's open problem (`docs/plans/batch.md` 3.8), not the core's.
- **Container**: `Environment::container()` builds every CAB's preload index first (`environment.py:208-216`) and lists every non-dependency `SerializedFile`'s container rows, CABs in registry order, as an iterator (`ContainerItems`; `Environment::objects`, `Environment::files` and `Registry::keys` are iterators too), so a listing allocates nothing per record. `container::read_container` reads the first AssetBundle in dict order (`m_Container` pairs in file order, repeated paths kept, and `m_PreloadTable`) into a `Container` built from `MeteredVec`s. **`path_dict`** (review round 1: it was not kept): `Environment::container_path(&ObjectRef)` is `obj.container` (`files/ObjectReader.py:199-204`): the index built first, then the object's file's `path_dict`, whose initial entries map each row's asset path id to its path (the last row winning; a row whose asset names another file keys nothing, `PARITY.md` section 19.2) and to which the preload adds, in the target's file, the path of the first row whose span reaches an object without one (`setdefault`), each entry stamped so that two passes at once leave what one after the other would (`container.rs` module docs). The preload is linear in rows, table and externals (decision 11), where UnityPy's loop is quadratic when spans overlap: each table index is dereferenced once per walk, at the first row whose span reaches it, which is the row whose `setdefault` UnityPy keeps, and each external looked up again only where UnityPy's next lookup could answer otherwise (`EnvStats::preload_dereferences` counts the dereferences; `PARITY.md`'s `parse_preload_table` row). Where a dependency may be evicted (any options but `unitypy()`'s), its file's paths would go with an eviction, so `container_path` refuses its objects (`Unsupported::EvictableContainerPath`, a `PARITY.md` section 19.3 row); which file keeps them for the batch engine is the batch plan's to decide.
- **Dependencies** (what `find_file` and resource reads load, and what a caller loads with `Environment::load_dependency(source)`, the same load made directly: UnityPy has no such call) each get their own meter under `Reservation::Dependency` and are kept in an LRU bounded by `EnvOptions::dep_cache_bytes`, the sum of their meters; `load_dependency` never adds the file to `files`, and resolver loads do only under `keep_resolver_loads` (above), whose `unitypy()` options never evict. Evicting one drops the LRU's handle on it, which returns its runs, its parsed entries and, for a source that can be read again (`Source::Path` re-read, `Source::Fetch` re-fetched), its bytes and their charge, once nothing else holds them; a `Source::Bytes` dependency keeps its bytes, which are the caller's. Its registry slot keeps what reopens it, and the next read opens it again (header and directory again, its decodes charged again) on `Meter::reopen` of its meter (3.6): the same memory account, so the input's bound holds across its opens, and the new open's own work allowance, so a dependency evicted and reopened by every job never exhausts it, while a handle of the old open that something still holds (a nested bundle a resource read kept after the LRU dropped its outer handle) goes on counting against the old open's allowance, which nothing resets. A dependency read the pool refuses evicts and retries once, then fails with `Error::Budget` naming `Dependency`; the refusal is not cached (3.1), so a later read with room in the pool succeeds. Files the caller loaded are never evicted. `EnvOptions::unitypy()` never evicts, a pool refusal included (`dep_cache_bytes` at `u64::MAX` with `keep_resolver_loads`: the refusal then fails the read). The LRU's work per use is constant (review round 1: a use scanned and summed every entry under its mutex): a linked list over a map, its byte total kept as each dependency's meter changes, and a dependency that nothing can reach any more (every key it registered was registered again, as `find_file` reloads a file that does not register the name asked) leaves it without counting as an eviction. Each registered file's preload table is walked once, an eviction notwithstanding: the mark lives in its registry slot, which outlives the eviction.

### 3.14 Errors

`error.rs` (scaffold, frozen) holds one `Error` with structural variants: `Detect`, `OutOfBounds`, `Malformed`, `Unsupported(Unsupported)`, `Decompress`, `Version`, `TypeIndex`, `Tree`, `AssetBundle(Box<ParseError>)`, `Entry { name, source }`, `Limit`, `Budget`, `NotFound`, `Deref(Box<DerefError>)`, `Io(IoError)`. `Error` is `PartialEq + Eq` (so `DerefError` and `ParseError::Deref` are too): `IoError` wraps the shared `std::io::Error` and compares kinds and OS codes, since `std::io::Error` has no equality. `LimitKind` names one variant per bound (`InputMemory` for the meter, `InputBytes`, `BlockOutput`, `DecodeWork`, `Inflate`, `ContainerDepth`, `TreeDepth`, `ValueDepth`, `ValuesPerObject`, `ZeroSizeElements`) plus `Count`, and a refused charge converts to `Limit` (the input's bound) or `Budget` (the pool's, tagged with its `Reservation`); `OutOfBounds::pos` is the signed reader position (3.3); `DerefError` separates `FileIdPastEnd` from `FileIdBelowStart` and has `ContainerDropped` (3.13). `Error`, `TreeError` and `ParseError` implement `once::CellError`, which says which variants are transient (never kept by a cell) and what heap a kept one owns (3.1). `walk::ParseError` is an object's L2 outcome (`l2_kind()` maps to the dump's kinds, a `CheckRead` whose `bytes_read` is negative to `other` as the oracle does, 3.10); `walk::WriteError` is L3's, with `NoTypeTree { class_id }` for an object with no tree (UnityPy raises the read's `TypeTreeError`, `files/ObjectReader.py:296-307`) and `Tree(Box<ParseError>)` for a tree that did not resolve (D request 4). All are `Clone + Send + Sync`. A new variant goes through package E (section 7.1); the enums are `#[non_exhaustive]`.

### 3.15 Limits and no panics

- **One rule: everything the core allocates in proportion to an input-chosen size is charged to the input's meter first.** Each input (a top-level file, every bundle nested in it and every file in those) has one `limits::Meter`, made by the load (`Meter::for_input`) and passed to every parse. A charge is made before the allocation it pays for, and a charge that fails allocates nothing. The charge (`limits::Charge`) lives inside what it paid for and returns when that drops, so retained results stay counted: a `Parsed` keeps the charge for its values, a decoded `Bytes` the charge for its buffer. The meter books every charge with the context's `MemoryBudget` as well, so a batch budget sees what every input holds. The sites:

  | what | charged through | test |

  | a path's bytes (`Source::Path`, and each input `unityrs dump` reads, `unityrs_dump::read`, whose refusal is its input's own record and the run goes on) | `env::read_path`: refused above `max_input_bytes` before a byte is read; one buffer at the stat'd length, charged first and filled, then the end checked with a read into a fixed stack buffer, so a file that ends where its length says costs exactly its buffer, never a growth past it; only a file that outlasts its stat'd length (one growing while read, a pipe, a device) grows the buffer, charged as it grows, stopped at the bound; read, not mapped, because a mapping of a file another process truncates faults (`SIGBUS`) instead of failing, and it needs no new dependency | `env::tests` (a path needs only its own size from the meter and the budget) |

  A charge is `heap_cost(bytes)`, glibc's chunk for the request: the request plus the 8-byte header rounded up to 16 bytes, at least 32; and a chunk of 128 KiB or more is `mmap`ped, its request plus 8 rounded up to a page (`limits::tests::heap_cost_is_glibcs_mmapped_chunk_at_every_residue`). So a charge covers the allocator's rounding too; during a growth the old and the new allocation are both charged until the old one is freed. Charges and permits merge **by meter and by pool**, so an owner keeps one record per meter and per pool however often it grew, and the record is part of the owner's charged struct, not a growth of its own.
- **The bound.** One input holds at most `Limits::max_input_memory` (default 8 GiB) plus a constant: the meter and its memory account (`Meter::OWN_HEAP`, 128 bytes in glibc chunks, and `Meter::REOPEN_HEAP`, 64 more, per reopen of an evicted dependency), per caller buffer the core clones (the input's bytes, a `RawStr` name made from a `Vec` or a `&str`), the 24-byte shared header `bytes::Bytes` allocates on its first clone (32 bytes in glibc chunks), uncharged when the core makes that clone, so at most two per top-level input (C request 8; `files_memory.rs` clones the caller's name and data before its baseline); and per thread reading it, that thread's stack (recursion is bounded by `max_container_depth`, `max_tree_depth` and `max_value_depth`; a read or a write of one object needs `Limits::stack_needed`, and the dump's workers get twice that and `unityrs_dump::run::CONTAINER_LEVEL_STACK` for each container level the depth bound allows), detection's scratch (at most 64 KiB, 3.5) and the 1 KiB thread-local tally of the lazy computations it is running (`limits::GrantScope`, a fixed array, 3.1). Per `FileContext`, not per input, the provider chain's cache holds at most 64 MiB of slots and keys and 65,536 entries (3.12), and providers keep their own data (a TPK's trees, one per release root, its walks bounded together at `TpkProvider::MAX_TOTAL_ROWS` rows, kept or not, on each thread, 3.12, and its tables and common-string table charged to its own meter as they grow); per `Environment`, the registry's two tables' fixed parts (3.13). `tests/memory_model.rs` reproduces it (section 10): a counting allocator counts the heap in glibc chunks (`heap_cost` of each request, the unit the meter charges, so an uncharged allocation cannot hide in another's rounding) and checks that it never holds more than the meter has charged on the paths above, with no slack, each run once with an `Unbounded` budget and once with a `Counting` one (a batch's budget, whose permits are bookkeeping of their own); `heap_cost` is checked against glibc's `malloc_usable_size` at every residue below each page multiple it samples and around the 128 KiB threshold; and the two hostile inputs of round 2's review, scaled to a 64 MiB meter (twelve parses of one 8 MiB table, as overlapping directory entries make; 528 nested spans over a 32-block bundle, as lazy re-decodes make), stop with `LimitKind::InputMemory` after 7 of the 12 parses and 110 of the 528 runs, under both budgets. A caller with bigger inputs raises the limit; a batch engine's budget bounds the sum over inputs (4.1).
- **The other bounds** are on work and nesting. Defaults (scaffold): `max_block_output` 1 GiB (one block's actual output); `max_decode_work` 32 GiB (work per open of an input: bytes decoded, bytes a bundle entry's gzip detection reads and inflates, bytes a parse searches or indexes, a bundle read's steps, bytes granted to lazy computations that ended unkept, to entry parses that failed and to AssetBundle reads beyond the container they keep, the work of every read and write of a value; not returned while the open lives, 3.6, 3.1, 3.10); `max_inflate` 4 GiB (streamed, never held); `max_input_bytes` 4 GiB; `max_container_depth` 16; `max_tree_depth` 256; `max_value_depth` 512; `max_values_per_object` 2^26 (work per object read or write: values, and children skipped); `max_zero_size_elements` 2^20; `max_prealloc` 2^16 elements. Exceeding one, or the meter, is `Error::Limit`/`ReadDetail::Limit`/`ReadDetail::Charge`, never a crash, and a test trips each (`limits::tests`, `budget::tests`, `env::tests`; packages B and C add one per limit they enforce). `PARITY.md` lists each as a safety divergence where UnityPy would exhaust memory or the stack, and the meter under `Lazy` as 3.13's difference (d).
- **No count sizes an allocation, no arithmetic wraps.** Table growth follows 3.3. Input integers are combined in a wider type (`i64` offsets in `i128`, `i32` ids in `i64`) or with checked operations, because Python's integers never overflow and a wrapped value is a wrong answer in release and a panic in the debug builds the no-panic tests run in.
- `lib.rs` denies `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `unreachable` and `indexing_slicing` outside tests. A stub module's `todo!()` is allowed only by its `STUB(X)` line, which the owner deletes with every `todo!()`; G6 (`scripts/stub-check.sh`) fails the gate while any `STUB(` marker, stub allow or `todo!(` in code remains under `crates/` (section 6).
- Every package adds seeded no-panic tests: its builders' output mutated by `testkit::Rng` (bit flips, truncation), 10,000 cases per module in CI, asserting `Result`, never a panic.

### 3.16 Send + Sync and threads

The crate asserts `Send + Sync` at compile time for **every** public struct, enum, union, trait object and type alias (`unityrs-dump` does the same for its own; an alias counts, since `pub type Shared = Rc<u8>` is a public type a caller holds): `const _: () = crate::send_sync::<T>();`, in `lib.rs` or next to the type. A test (`every_public_type_is_asserted`, through `unityrs_testkit::public_types::unasserted`) scans the sources and names each public type by its full module path, so it fails when one is not asserted, even if it shares a name with one that is, and a package that adds a type adds the line beside it without editing the frozen `lib.rs`. The core keeps no global state (no statics with interior mutability), spawns no threads, and never blocks inside a call: `MemoryBudget::try_reserve` refuses instead of waiting (`tests::the_core_starts_no_thread_and_never_waits` scans the sources for thread starts, sleeps, parks, spin hints, condition variables, barriers and channels, a call matched with a turbofish or spaces before its parenthesis too). **No lock is held across user code but a budget's, and no value is computed inside its cell.** Locks are `OnceLock`s filled only by `once::get_or_publish` and `get_or_publish_result` (the compute runs with nothing held; the only thing that runs inside the cell is a move), `RwLock`s for the provider cache, the registry and the Environment's `files`, and `Mutex`es for a bundle's runs, a file's `path_dict`, the Environment's LRU, each dependency's `open` (its handle and its meter, one lock: review round 6 found the meter under a lock of its own, taken while `open` was held) and the walks' watch map. Each is held only to look up or publish, never across a decode, a parse, or a call into user code (a `TypeTreeProvider`, `CabResolver`, `Fetch` or `BlockCodec`), and none is taken while another is held. **The one exception is the budget:** publishing may grow a table (a bundle's runs, the registry) or replace a value, and that growth or release is charged to the meter, which books it with the `MemoryBudget` (`try_reserve`), and a release returns bytes to the `PermitHome` (`release`), with the lock held. Their contract (`budget/mod.rs`) is therefore that they never block, never call the core, and never take a lock a core caller may hold while calling the core (Python's GIL among them: a Python budget is a counter the binding keeps in Rust, never a Python callback); and that one pool is one home, so permits merge by home. So a callback may re-enter the core, even the value it is computing (the inner call computes and publishes, the outer one's value loses), and a thread holding an outside lock, Python's GIL among them, never waits on a computation that needs that lock. The price is duplicate work when two threads ask for one value at once; the loser's value and its charges are dropped. `once::tests` pin both deadlocks round 2 probed (re-entry, and a lock the compute needs held by a waiter), each failing past the deadlock guard instead of hanging (`unityrs_testkit::guard`: ten minutes, beyond any delay a loaded machine adds, so only a hang reaches it), and a source scan (`tests::every_cell_is_filled_through_the_once_helper`) fails on any cell-filling method or type named outside the helper's own file `src/once.rs` (by a call, a turbofish or a path; `call_once_force` with `call_once`; a `once.rs` elsewhere in the tree is scanned). A lock is checked by a test of each public path that takes one, re-entering it and holding an outside lock its callback needs (`provider::tests`; C's and D's, 4.1).

**The Environment's shared structures** (fix pass 5: rounds 3, 4 and 5 each found a structure broken by the previous round's local fix, so each keeps the invariants below under every interleaving of the operations that touch it, each by one mechanism, and a test forces every pair of those operations through each point between their steps, `crate::env::gate`, then a randomised multi-thread run checks the invariants after every step). The owner of each lock is the one module that takes it; no lock is taken while another is held (the budget aside, above). Every guard on one of the Environment's locks (the registry's, `files`, the LRU's, a dependency's `open`, the watch map) is made by `env/held.rs`, which in a unit-test build counts the guards each thread holds and panics on one taken while another is held, so every unit test that runs an Environment checks the rule.
1. **Registry and its slots** (`env/registry/mod.rs` and `register.rs`: one `RwLock` over the key order, the key table and the lists of dropped slots). **R1** the dict by rank: a key's position is its least rank and its value its greatest, whatever order the registrations arrive in, from whichever thread; an equal rank is no change. **R2** charges: a registration is charged, before it allocates, to the meter of the input its slot belongs to (a dependency's meter for a dependency's slot, whichever handle read the entry: review round 5 found a batch job's meter paying for shared entries it outlived; an entry slot's bundle's meter otherwise), and its charges drop after the lock, with the slot.
2. **Reach and settle** (`env/registry/reach.rs` and `pending.rs`; the lists are the registry's, under its lock). **R3** every reader settles: no load's registration, lookup by name, key listing or container pass returns while a slot listed before its `settle` began is unreached, but for a refusal and for a slot whose dependency the LRU evicted, which a `settle` moves to a second list that only the container pass reaches, opening the dependency again (Q13, revised after review round 6); every `settle` reaches every listed slot, those another thread is reaching included (a reach is safe for concurrent callers), and a slot leaves the lists only once reached, found to hold nothing or refused for good (review round 5: a `settle` popped a slot and a concurrent one returned on the empty list). Each list is a B-tree in the order the slots were listed, so each step (listing a slot, finding the next, taking one off) takes O(log n) for n listed and counts as its slot's input's work, 8 bytes a step (review round 6: a front removal from a `Vec` made settling m slots O(m²), uncounted). **R4** a slot leaves the table and joins a list in one step, under the write lock; a container's slot is marked reached only after its whole subtree is registered; a dropped slot is not listed only when the key's value stands in for it, which every handle on the dropped entry can tell (`entry_of`), a reader inside the dropped entry then reaches the standing slot, and the standing slot's entries take the least dropped load as their positions (Q14, revised after review round 6). A registration that lowers that load on a slot already the key's value then reads whether the slot is marked reached; a reach reads the load before it registers and again after it marks the slot, and registers again at a lower one; all of it sequentially consistent, so one of the two sees the other, and a registration that finds the slot reached lists the dropped slot as any other. **R5** work: a reach is a lazy computation of its slot's input, so what its registrations were granted before the input's own meter refused them counts as that open's work, and past the allowance the reach is refused with `DecodeWork`, kept.
3. **The listing and the walks' watches** (`env/listing.rs`'s `files` lock; `env/watch.rs`'s map mutex and walk count). **W1** a walk that read a key sees every change to it published after the read: the walk's flag is set up before its lookup reads, and every publication (a registration, a `files` entry) calls `notify` after it publishes, unconditionally, `notify` deciding then whether a walk runs (review round 5: the listing decided before it published). **W2** a walk's watches are charged to its meter by a charge the walk itself holds, released only after its entries have left the map and every key list it grew has shrunk back to what the running walks pay for.
4. **The preload memo and the container index** (`env/container_index.rs`: a walk's own `Targets`, the registry's `built` mark). **P1** a pass is marked built only when it ended or failed with an error the input decides, never on a refusal (budget, meter, I/O); what a walk the file's own meter refused was granted counts as that open's work (review round 5: a refused pass was kept). **P2** a walk reuses a kept answer only while its flag is unset (W1), and its flags drop before its watches end (W2).
5. **The dependency LRU** (`env/registry/lru/mod.rs`: one `Mutex` over the list and the map). **L1** every step leaves every key the map holds listed once and nothing else listed; **L2** the byte total is the sum of the entries' meters as last read; **L3** an eviction takes at most as many steps as the LRU held at its first (review round 3).
6. **What another thread sees** (review round 6: this section and `env/mod.rs` said concurrent calls act as if made one after another, which a load or a reach seen midway does not). Each key's registration, each `files` entry and each `path_dict` entry is published whole; a load's or a reach's set of keys is not published at once, so another thread may find one of its keys and miss a later one; a call that reaches a container returns only after its whole subtree is registered, and a load only after its keys and its `files` entry are.
The tests: R1 to R5 by `env/registry/reach_tests.rs` (every pair of a load that drops a container, a reload whose container stands in, a lookup that resolves one, a lookup by name, the key listing and the container pass, each stopped at each point; a reach that learns a lower position while it runs, both ways round; and a random four-thread run), `env/registry/pass_tests.rs` (the pass's reopen of an evicted dependency's dropped slot, every pair with another pass, an eviction, a lookup by name and the key listing, each stopped at each point) and `tests/env/reach.rs` (R5, and `settling_dropped_slots_counts_steps_that_grow_as_m_log_m`: the lists' steps, counted on the input's meter); W1, W2, P1 and P2 by `env/preload_tests.rs`, `env/watch/tests.rs`, `tests/env_fixtures.rs` refused and, for P1's count of a refused walk's work, `tests/env/reach.rs` `a_pass_the_meter_refuses_is_counted_until_it_is_kept`; L1 to L3 by `env/registry/lru/tests.rs`; 6 by `env/threads_tests.rs`; the rule that no lock is taken while another is held by every unit test (`env/held.rs`).

### 4.2 Python (P3)

`unityrs-py` maps `Environment`, `BundleFile`, `SerializedFile` and `ObjectRef` to UnityPy's classes one to one (`env.files` from `Environment::files()`, resolver loads included, under `EnvOptions::unitypy()`); `load()` uses `LoadMode::Eager`, so UnityPy's load errors surface where UnityPy raises them. `Value` converts to Python objects without a typetree: `Str` with `surrogateescape`, `F32` through the double widening, `Tuple` to `tuple`, `Prims::U8` to `list[int]`, `Dict` keys through `Parsed`'s lists. Every binding call into the core releases the GIL, not only reads: a `bundle.files[...]` lookup parses an entry, which may run a codec or a provider, and a Python callback re-acquires the GIL (a budget never does: the bindings' budgets are counters kept in Rust, 3.16). Because the core holds no lock across a callback and computes no value inside its cell (3.16), the GIL cannot invert against a core lock (every type is `Send + Sync`). **`fork()`**: the core holds no threads or global state, but a read in another thread may hold a bundle's run `Mutex`, a registry or provider `RwLock`, or be publishing into a `OnceLock`, and a forked child would inherit that lock held by a thread that does not exist. The rule is therefore the one PyTorch and grpcio state: no core call may be in progress in another thread at `fork()`; the bindings document it, and a `multiprocessing` user picks the `spawn` or `forkserver` start method, or forks before the first read. A child-side reset (an `os.register_at_fork` hook re-creating every lock) was rejected: the locks live inside `Arc`s the core cannot enumerate, and a `OnceLock` caught mid-publish cannot be repaired. **Back-references**: UnityPy's objects point back (`obj.assets_file`, `assets_file.parent`, `parent.environment`); the core's `ObjectRef` and `Parent` carry the file and container handles, and the bindings keep the Python wrappers they built for them (a dict keyed by the core handle) so `obj.assets_file is f` holds; each wrapper of a file keeps a strong handle on its bundle, as UnityPy's `assets_file.parent` does, so `DerefError::ContainerDropped` (3.13) never reaches Python.

## 5. The dump and the CLI

`unityrs-dump` (E) writes `docs/CANONICAL_DUMP.md` format 1 from core's public API.
- **Order** (section 5 of the format): inputs in bytewise order of their relative path; each input depth-first: its `file` record, then a `SerializedFile`'s objects in ascending signed `path_id`, or a container's entries in `files` dict order, recursively. `-j N` dumps inputs in parallel (rayon) and writes them in order, so output does not depend on `N`.
- **Memory.** An input's records are held until the run writes them, and can be thousands of times the input (an object of 4 bytes read as 2^20 empty structs; every object record repeating a long container path), so each line is charged to the input's meter as it grows, and reserved fallibly: they count toward its `max_input_memory` with what its parse holds, past it they are its `InputMemory` refusal, and a refusal of the budget or the allocator, of the records or of any read of the input (an object's included, never its L2 outcome), is its `crash` record (`CANONICAL_DUMP.md` 4.2), never an abort of the run. So is what the dump holds beside them while it writes a record (the copies of the core's tables a file record's `l1` is built from, its path, the objects' order, which is the core's own by path id), and a typetree provider's tree refused memory, which the provider never keeps (`ProviderError::memory`). Every byte the dump hashes or compares (an entry's, an object's raw bytes and its resave's, a summarised value's) counts toward the input's `max_decode_work` before it is hashed, since rows, objects and values may overlap the same bytes (`PARITY.md` 19.3, "the dump's hashing"). The run writes the lines one by one; at most `2N` inputs are held at a time. There is no bound over the inputs together: a shared budget would make an input's record depend on what the others held, and so on `N`.
- **A failing entry fails its input**: an input whose entry fails to detect or parse gets one `file` record with `parsed_as` `"error"` and `{"kind":"parse"}`, nothing else. The dump reads each input with `BundleFile::load_all` to get exactly that.
- **JSON** is written by hand, ported from the spike's `json.rs` (string escapes as Python's `json.dumps(ensure_ascii=True)`, the metadata-string rule), never through serde. Values encode from `Value` alone.
- **L3**: each object's value re-saved with `ObjectRef::write_typetree` under `WriteRules::UnityPy` and digested as the format says.
- **Context**: `FileContext::unitypy()` and nothing else: no shim, no fallback version, no override. A TPK path (`--tpk`, the oracle image's UnityPy TPK) feeds `unityrs-tpk` for stripped objects.
- **Output**: gzip level 9, mtime 0, written to `OUT.partial` and renamed when complete; the output path must lie outside the repository (as the oracle's).

**CLI** (`unityrs-cli`, E):
- `unityrs dump PATH... | --index FILE [--kind K] [--sample N] [--name GLOB] -o OUT [--levels L0,L1,L2,L3] [-j N] [--tpk PATH]`, the same selection flags as `tools/parity/unitypy_dump.py`;
- `unityrs values CASES.json`: the spike's value-case protocol (`{"name","endian","nodes","hex"}` in, one JSON line per case out), so `tools/parity/value_cases.py` (copied from the spike, which keeps its own so its script tests and CI's suite count are unchanged, 7.6; the copy is pointed at `unityrs`) drives it.

## 7. Work packages

### 7.0 What the review rounds taught: read this before writing code

The review rounds found the same few mistakes again and again. Each rule below is enforced by a test or a scan that will fail a package's merge, so it is cheaper to follow them from the first line.

- **Build values only through the metered builder** (3.9). `ValueBuilder::vec()` gives the `MeteredVec` a list, map, tuple or run grows in; `list`, `map`, `tuple` and `prims` (over a `PrimRun`) turn it into a `Built`, which carries its own charge; `scalar` wraps a value that owns no heap (it refuses a list, map, tuple or run with an allocation, but cannot see whether a `Str` or `Bytes` owns a plain `Vec`: pass it only slices of a charged buffer); a `Built` goes into its parent through `MeteredVec::push_built`, `push_entry` or `set_entry`, or into the `Parsed` through `finish`. Never build a `Value::List`, `Tuple`, `Dict` or `Prims` from a plain `Vec` or `Box`, never a `Str` or `Bytes` from a `Vec` the meter did not charge, and never push a plain `Value` that owns heap: the types cannot stop that, and B's counting-allocator test will (7.3). `Map::from_entries` is for a caller's own values, never the reader's.
- **Charge every input-sized allocation before making it** (3.15). Tables are `MeteredVec`s on the input's meter (`with_capacity`, `reserve`, `push`), grown towards a count the bytes can back (3.3), never `Vec::with_capacity(count)`; `Reader::read_i32_array` takes the meter; strings are zero-copy slices or `RawStr::charged`; registry and `files` entries are charged to the file that adds them (3.13); `MeteredVec::from_vec` is for memory that already exists (a TPK's rows, a test's), never for parsing input. A codec writes only into its `DecodeBuf` or returns `Decoded::Input(range)`, never bytes of its own, and every block is decoded through `codec::decode_block` (3.6). Each path a package adds gets a case in a counting-allocator test like `tests/memory_model.rs`: the heap above its start never exceeds what the meter charged.
- **One meter per open of an input** (3.6, 3.13). `Meter::for_input` makes it; every file of the open (its entries, nested bundles, parsed values) charges that meter; an evicted dependency opens again on `Meter::reopen` of its meter (the same memory account, its own work allowance), never a fresh meter (which would escape the input's bound) and never a reset of the old one's work (which a handle still alive may be adding to). `Meter::unlimited()` is for a caller's own values and tests only.
- **Every lazy value goes through `once::get_or_publish` or `get_or_publish_result`** (3.1, 3.16). Nothing else fills a cell outside `src/once.rs`: no `get_or_init` (with or without a turbofish), `get_or_try_init`, `LazyLock`, `LazyCell`, `OnceCell` or `call_once`/`call_once_force` (`tests::every_cell_is_filled_through_the_once_helper`). A new error type a cell keeps implements `once::CellError`: `is_transient` (a budget, meter, I/O or provider refusal, never kept), `is_meter_refusal` (the input's own meter, `InputMemory`, and nothing else) and `work_refused` (the kept `DecodeWork` refusal once the open's work is used up). A transient error is never cached; what its computation was granted on its own thread counts as the open's work only when the meter itself refused it (round 6: counting every transient failure, and every thread's grants, let contention poison a valid dependency).
- **The core never waits, spins or starts a thread** (4.1). No `std::thread` (but `available_parallelism`), sleep, park, `yield_now`, `std::hint::spin_loop`, `Condvar`, `Barrier`, channel or thread pool, however imported or called (`tests::the_core_starts_no_thread_and_never_waits`); a budget is only ever asked (`try_reserve`), never waited on. No lock is held across caller code (a codec, provider, resolver or fetcher): look up or publish under the lock, compute with none held, and add a test that re-enters the path from inside the callback, and one where the callback needs a lock another thread holds, each under the deadlock guard (`unityrs_testkit::guard`).
- **Every public type is `Send + Sync`, asserted in its own file** (3.16): a `pub struct`, `enum`, `union`, `trait` (as `dyn`) or `type` alias gets `const _: () = crate::send_sync::<T>();` beside it; `tests::every_public_type_is_asserted` names each by its full module path, so a re-export or a same-named type elsewhere does not count.
- **No panic on any input** (3.15). `lib.rs` denies `unwrap`, `expect`, `panic`, `todo`, `unimplemented`, `unreachable` and indexing outside tests: use `get`, checked and saturating arithmetic, and the signed Python positions of `stream.rs` (`py_read`, `py_unpack_from`, `py_align`, `py_string_to_null`), which go negative and past the end as UnityPy's do. Every package adds seeded no-panic tests over its builders' mutated output (3.15).
- **Port, don't invent.** Every rule cites the UnityPy 1.25.2 or UnityPyBoost line it ports. When the plan and UnityPy disagree, a probe in the oracle container decides and UnityPy wins; the package records the disagreement as a request (below) so the plan is fixed. Several round-5 findings were exactly that: a plan sentence that a probe proved wrong (3.13's resolver loads, 3.10's read order outside an array, rabex's one-root TPK classes).
- **Each test must fail without the code it covers.** A fix or rule is proved by running its test against the code before the change (or a mutant of it in a copy under `/tmp`) and seeing it fail; reviewers re-run these mutants. Fixtures are synthetic, built in code (`tools/fixtures/<package>.py`, with `--check`), and committed only as small hex and JSON; no game data, no corpus file, bundle or asset names, no host paths (decision 10; this repository is public).
- **Numbers in a doc come from a command in the branch**, named in section 10; a re-measured number replaces the old one.
- **Frozen files: ask, do not edit.** A change to a file a package does not own (a scaffold file, `lib.rs`, an `Error` variant, a `Limits` field, a signature another package calls) is written as a numbered request in `REQUESTS-<package>.md` at the worktree root (what, why, the exact signature or text), worked around in the package's own files where it can be (a private helper), and made by the integration step (7.1, Ownership).
- **Stubs.** Delete the `STUB(X)` allow and every `todo!()` in the files the package owns; `scripts/stub-check.sh` lists what is left, each hit with its owning package. A test that waits on another package's stub is `#[ignore = "STUB(Y): ..."]` (7.1).

### 7.1 Rules for every package

- **Branching.** Each package works in its own worktree: `git worktree add .wt/p1-<x> -b p1-<x> p1-core` (x in a-e). Merge order into `p1-core`: **A, B, C, D, E**, each rebased on what merged before it. Every package must pass `cargo fmt --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings` and `cargo test --workspace --locked` at every commit it merges.
- **Ownership.** A package edits only the files it owns (2.2 and below). The scaffold files are frozen: a needed change to a shared signature, an `Error` variant, a `Limits` field or another package's file is written as a numbered request in `REQUESTS-<package>.md` at the root of the package's worktree (what, why, the exact signature or text), worked around in the package's own files meanwhile where it can be (a private helper), and made by the integration step (E) in one integration commit, which removes the request; a request that a probe shows the plan wrong also fixes the plan. A package that adds a public type asserts it `Send + Sync` in its own file (`const _: () = crate::send_sync::<T>();`, 3.16), so it never edits `lib.rs` for that.
- **Blocked tests.** A test that cannot pass until another package lands is committed `#[ignore = "STUB(X): <what it waits on>"]`, X being the package it waits on. G6 fails while any remains, so it cannot be forgotten: the package X un-ignores it in its own merge (the merge order puts X after the test's author, or E does it at integration), and that is in X's "Done when".
- **Dependencies.** Core's dependency list is final, its one dev-dependency (`serde_json`, pinned, to replay fixtures) included. Only A changes `Cargo.lock` (new crates `unityrs-rabex`, `unityrs-tpk`), and E (the dump's and CLI's dependency on `unityrs-tpk`). Others resolve lock conflicts by taking the merged base's lock.
- **Tests are synthetic.** Inputs are built in code with the testkit; expected results come from the oracle. A package that records fixtures adds `tools/fixtures/<package>.py` (runs in the oracle image, builds inputs in code, runs UnityPy 1.25.2, writes the inputs as hex and UnityPy's results as small JSON under `crates/unityrs-core/tests/fixtures/<package>/`, one case per line, with a `--check` mode that regenerates and compares); `cargo test` replays them without Python. The scaffold's own fixtures are the model: `tools/fixtures/scaffold.py` writes `tests/fixtures/scaffold/{reader,pptr_external,lz4_blocks}.json` (the reader's position rules, `external_index`, and liblz4's verdict on boundary LZ4 blocks), and `tests/scaffold_fixtures.rs` replays them. No corpus byte, name or path enters a commit.
- **No stubs at merge.** A package deletes its `STUB(X)` allow and every `todo!()` in the files it owns; `scripts/stub-check.sh` lists what remains, each hit with its owning package, and a count per package (G6). Every stub the scaffold left is marked, so the list is complete: B, C, D and E's modules carry a `STUB(X)` at the top; A's are the generated tables the scaffold ships empty or seeded (`classid::CLASS_NAMES`, `tables::ND_ZEROS` and `LOWER_EXCEPTIONS`, `commonstring::COMMON_STRINGS`), each marked `STUB(A)` on its own line, which the generator's output does not carry; A's new crates (`unityrs-rabex`, `unityrs-tpk`) have no stub, since they do not exist yet.
- **Milestones.** Each package pushes its interface milestone first (listed below); other packages may merge that branch into theirs read-only to unblock tests, since files do not overlap.

**Open:** none (Q11 to Q14 were decided on the recommendation on 2026-10-30; see below). **Decided** (with the reason):
- **Q5. Offering the fork's fixes upstream: done** (the owner's approval, 2026-10-29). F2, F3, F5, F6 and F7 went to rabex as pull requests #2 to #6. They no longer bear on unityrs, which dropped rabex (below).
- **Q11. The container preload keeps the linear bound** (decided on the recommendation, 2026-10-30; the owner may revisit). Through an external `find_file` loads again (one found by suffix under a longer name), UnityPy dereferences every (row, index) pair over overlapping spans: quadratic in the rows, with the kept copy holding the last row's path. unityrs dereferences each index once (decision 11), so the kept copy holds the first row's path. Repeating UnityPy would make a hostile container quadratic. The difference needs that pathological input, so it is admitted as `PARITY.md` 19.3's row of that name, pinned by `tests/env/container.rs` a_preload_external_found_by_suffix_loads_at_each_dereference.
- **Q12. Same-named CABs take the own-bundle-first rule (Tier C) in P2, under `EnvOptions::batch()` only** (decided on the recommendation, 2026-10-30). The batch engine is where one bundle's `.resS` and container must not take another bundle's CAB, while `EnvOptions::unitypy()` is the parity mode and keeps UnityPy's one registry (Tier A) under both load modes. P1 implements UnityPy's registry under every option set. P2's plan (`docs/plans/batch.md`) takes the rule and its tests.
- **Q13. Lazy reopens an evicted dependency to reach a nested container its dropped slot held, in the container pass only** (decided on the recommendation, 2026-10-30; revised on the recommendation after review round 6, 2026-10-30). Only `EnvOptions::batch()` evicts, so `unitypy()` is exact. As first decided, nothing reopened it: the miss looked like Q10's lookup by name. Review round 6 showed it is not: the dropped container's tables set paths in other files, so the container pass gave `container_path` of a file the caller loaded `None` where UnityPy gives a row's path. The revision: a load's or a lookup's `settle` still does not reopen it (a lookup by name keeps Q10's rule) but moves the slot to a list of its own, and the container pass reaches that list, opening the dependency again, once per slot (`env/registry/reach.rs`, `settle_for_pass`). The cost is one reopen and parse per such drop per pass that finds it, which an eager pass pays too to walk an evicted dependency's table.
- **Q14. Lazy lets a reload's slot stand in for the earlier load's, at the earlier load's positions** (decided on the recommendation, 2026-10-30; revised on the recommendation after review round 6, 2026-10-30). The entries have the values `Eager` gives them. As first decided, their positions in the key order followed the reload's, to save reading the dropped entry and registering its subtree once more. Review round 6 showed the cost of that: the container pass walks keys in their order, so `container()` listed the rows in another order and `container_path` gave an object the path of another row than UnityPy's. The revision: the standing slot registers its one parse's subtree at the dropped slot's positions (the least load it stands in for, `Slot::position`), with its own values, so no extra read or parse is made (3.13 (b), 3.16 R4; `env/registry/register.rs`, `Stand`). Since review round 5 a reader inside the earlier load's container reaches the standing slot, and only a reload on the same `Bytes` stands in (a reload no handle can tell is the same input is reached at the drop).

Every input-driven step counts toward `max_decode_work` (`DecodeWork`), as every other bounded kind of work does, and tests read the count from the open's meter.
