# tools/bench

The benchmark suite: unityrs against UnityPy 1.25.2 with UnityPyBoost, on public synthetic fixtures
(`docs/plans/bench.md`). The fixtures are generated by `unityrs-bench gen` (`crates/unityrs-bench`) from the testkit's
builders with fixed seeds, never committed; `benchmarks/fixtures.json` records every file's bytes and sha256 at both
scales, with each fixture's inventory, and every run holds the files it times to it.

Both implementations run the same workload script, `py_workloads.py`: `--impl unityrs` does
`import unityrs as UnityPy`, with the unityrs wheel installed `--no-deps` into the oracle's venv, as CI's
`python-wheel` job does. Each run is a fresh process, and its timer covers only the scope its workload names
(`workloads.json`'s `timer`); setup and the digest that compares the two sides' outputs are outside it.

```sh
# The full comparison, or the gate scale's 3 quick rounds, in the dev container (UnityPy and the wheel):
scripts/dev python tools/bench/bench.py run --out DIR
scripts/dev python tools/bench/bench.py run --out DIR --quick
# The fixtures alone, checked against benchmarks/fixtures.json; --update records both scales after a builder change:
python tools/bench/bench.py gen --scale gate --out DIR
python tools/bench/bench.py gen --update
# The README's section and BENCHMARKS.md from benchmarks/wall*.json and benchmarks/gate.json:
python tools/bench/bench.py render [--check]
```

Fixtures are cached under `$UNITYRS_BENCH_CACHE` (outside the checkout) when it is set, else under the run's DIR.
`$UNITYRS_BENCH_BIN` names a prebuilt `unityrs-bench`; otherwise `bench.py` builds it with cargo.

**Publishing.** Only a run of `.github/workflows/bench-wall.yml` (`workflow_dispatch` on `main`, GitHub's
`ubuntu-24.04` runner) is published: a PR commits its `wall.json` artifact as `benchmarks/wall.json` with the
rendered docs, and CI's `check --wall-run` step verifies the run (its workflow, event, branch and conclusion, no
change since its commit to the measured paths, which are the workflow, the inputs and every repository module the
measurement imports, and the artifact byte-equal to the file). A run on an emulated host, at the gate scale, with
fewer rounds than `workloads.json` names or missing a workload is refused.

**Another runner CPU.** GitHub's runners differ in CPU model between runs, and some rows move with it. To publish a
run on a CPU `wall.json` does not hold, commit its artifact beside it as `benchmarks/wall-<cpu>.json` (say
`wall-epyc.json`), byte-equal, and run `render`: the README and BENCHMARKS.md then show one summary table per
CPU, `wall.json`'s first. `check --wall-run` verifies every results file a PR changes; `render` refuses a
`wall-<cpu>.json` without `wall.json`, or two files on one CPU.

**The gate.** CI's `bench-gate` job (`ci.yml`) counts instructions instead of timing: in `debian:bookworm`, pinned
by digest, with valgrind from `install_valgrind.sh`, `bench.py gate` runs each workload's Rust scope
(`unityrs-bench run WORKLOAD FIXTURE`, `crates/unityrs-bench/src/work.rs`) once under callgrind at the gate scale and
compares the bench binary's own instruction count (`ir_own`), its allocation calls and the bytes it allocates with
`benchmarks/gate.json`, within ±1% both ways (`callgrind.py`). libc's count is recorded, not gated. Each workload's
mode (`calibrating` reports, `enforcing` fails) and the tolerance come from the base branch's gate.json; the counts
from the PR's. A pull request's job runs the PR's own checker, so the job warns when a change edits it (decision 7).
A change that moves a count commits the job's uploaded `gate.json` in the same PR.

```sh
# Locally, x86-64 only (counts from an emulated host are for comparison, not baselines):
sh tools/bench/install_valgrind.sh PREFIX
python3 tools/bench/bench.py gate --valgrind PREFIX --out DIR [--repeat N] [--workload NAME ...]
```

**Failures.** A scope that raises is a result, published as `raised:` and the exception's class name (unpaired). A
child that crashes, is killed (even from outside: a measured run is never run again), fails its setup or prints
no valid result (its keys, their types, finite numbers) stops the run with no `wall.json`. Children's stderr is kept
in `DIR/logs` only, never in the console output or `wall.json`.

| file | role |
|---|---|
| `bench.py` | the driver: `gen`, `run`, `gate`, `render` and `check --wall-run` |
| `callgrind.py` | the gate's callgrind runs, scope checks, per-object sums and verdict against the base branch's policy |
| `install_valgrind.sh` | bookworm's valgrind 3.19.0 deb, sha256-checked, unpacked without root |
| `py_workloads.py` | one run of one workload by either implementation, in a fresh process; prints its result as JSON |
| `results.py` | wall.json's schema, pairing, aggregation and the rendered README section and BENCHMARKS.md |
| `workloads.json` | the workload table both sides read: fixture, operation, timer label, PARITY.md row and tier |
| `tests/` | the self-tests (below) |
