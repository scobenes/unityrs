# CLAUDE.md

Guidance for agents working in this repo.

## Build and test

Development happens in the `unityrs-dev` container: a persistent satellite built
from a pinned image (`unityrs-oracle:upy1.25.2-2026-10-28`) that holds the parity
oracle (UnityPy 1.25.2 with UnityPyBoost, Pillow 9.5.0, texture2ddecoder 1.0.5,
astc-encoder-py, etcpak) beside the Rust toolchain. Run everything through
`scripts/dev`, which execs as the host user and overrides host-only linker
settings:

    scripts/dev cargo test --workspace
    scripts/dev cargo clippy --workspace --all-targets -- -D warnings
    scripts/dev python tools/parity/...    # the oracle side
    scripts/dev python scripts/unittest-suites tools/parity/tests=N ...   # the Python suites, as CI runs them

CI's `parity-py` and `scripts-py` jobs name a minimum test count per Python
suite (a suite that runs fewer fails, so a test module discovery stops finding
cannot pass unseen); raise it in `.github/workflows/ci.yml` when you add tests.
Pin a new action to a full commit SHA with its tag in a comment, and give a
new job a `timeout-minutes`; `scripts/tests/test_ci_workflow.py` checks both,
on the workflow as YAML. It needs PyYAML, which the container's Python lacks:
`scripts/requirements-tests.txt` pins the wheel for a venv of its own.

Never `docker run` / `docker rm` / `docker stop` anything. The container has a
12 GB memory cap; never remove the cap.

Git in a worktree under `.wt/` needs `GIT_DIR=/work/.git/worktrees/<name>
GIT_WORK_TREE=/work/.wt/<name>` inside the container, because the worktree's
`.git` file names a host path. A script that makes a scratch repository
(`git init`) must unset `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and
`GIT_COMMON_DIR` for it first: inherited, they
make `git init` write `core.worktree` into the main repository's config and its
commits land on the worktree's branch.

## Rules

- **Never commit game data.** Bundles from commercial games are not ours to
  publish. A corpus is a manifest of URLs plus sha256, kept outside this repo.
  Only synthetic fixtures, or fixtures built with the Unity Editor, are checked
  in.
- **Licences.** UnityPy, UnityPyBoost and AssetStudio are MIT and may be ported;
  keep their notices. Pillow ports carry MIT-CMU, liblz4 ports BSD-2-Clause and
  ports of CPython's standard library PSF-2.0. AssetRipper and other
  GPL/AGPL projects are read for format knowledge only; never copy their code.
- **Parity is measured, not assumed.** A behaviour claimed as UnityPy-equal needs
  a test against the pinned oracle. See `docs/DESIGN.md` section 3 for the tiers.
- **Third-party notices.** `THIRD_PARTY_LICENSES` is generated: after a change to
  `Cargo.lock`, `about.toml` or `about.hbs`, run `scripts/third-party-licenses`
  (it says how to install the pinned cargo-about), or CI fails. A port's notice
  goes into `about.hbs` (a section titled with the source, ending in the
  notice after a `{{!-- notice: LICENSE-<NAME> --}}` line), its source and
  licence into the file's header (`// Ported from <source> (<SPDX>): ...`),
  its licence into the crate's `license` as a term no `OR` choice drops
  (`(MIT OR Apache-2.0) AND MIT`), and the notice into the crate as that
  `LICENSE-<NAME>` file (or a link to another crate's), so the crate's
  package carries it. A text of ours a licence asks for (PSF's summary of
  changes) is a `NOTICE-<NAME>` file: cargo-about does not recognise a
  licence file with our words in it (the script's `ports` and `notices`
  checks). A file holding tables `tools/gen/gen_tables.py` writes says what
  generated them, from what, under which licence (`// Generated by
  tools/gen/gen_tables.py from <source> (<SPDX>): ...`), as `about.hbs`'s
  data provenance paragraph about it does (`ports` checks they agree). A file
  under a crate's `src/` that cites UnityPy's lines carries a UnityPy 1.25.2
  header (`Ported from` or `Generated by`), and a citation is `path:line` of
  UnityPy 1.25.2, with the path from the package root when two files share
  its name (`files/BundleFile.py`), a whole span (no blank first or last
  line; in Python no statement or function cut, in UnityPyBoost's C++ no
  top-level definition or brace block cut, its statements unread), and a
  bare `:N` (in backticks,
  opening a comment, or after a space or `(` in prose) only where its
  paragraph names the file before it (or, naming none, its section's "Lines
  are in `<file>`" or its file's Ported-from header does), never a line in
  words beside the file's name; `scripts/unitypy_citations.py` (CI's parity
  job) checks all of it, in every text file of the repository, reading the
  forms its docstring lists and no other. A new
  crate under `crates/` links `LICENSE-MIT` and `LICENSE-APACHE` to the
  repository's (`ln -s ../../LICENSE-MIT`), or the script refuses its
  template notice. A licence clarified or accepted for one crate in
  `about.toml` is mirrored in `deny.toml`, which the script checks.
- **A test's children and scratch.** A Rust test runs a child through
  `unityrs_testkit::child` and makes scratch with `unityrs_testkit::scratch`;
  a Python test or tool through `tools/parity/child.py` and
  `tools/parity/scratch.py`. A child killed by `SIGKILL` from outside (the
  OOM killer) is run again, never read as an answer, and a child's scratch is
  its parent's, removed however the child ends. Source scans
  (`child::direct_runs`, `scratch::direct_scratch`, `tests/test_child.py`)
  fail on a process or a temp folder made any other way.
