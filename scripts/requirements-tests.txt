# The scripts' own tests (scripts/tests) need the standard library, PyYAML
# and packaging: test_ci_workflow.py parses the workflows as YAML, since a
# rule read line by line misses what YAML can write another way (a
# flow-style step), and release_dists.py compares versions by PEP 440. For
# CPython 3.11 on manylinux x86_64, as CI's scripts-py job installs it into a
# fresh venv of its own:
#
#     python -m pip install --require-hashes -r scripts/requirements-tests.txt
#
# Wheels pinned by hash: PyPI's sha256 of PyYAML's cp311 manylinux x86_64
# wheel (https://pypi.org/pypi/PyYAML/6.0.3/json) and of packaging's
# pure-Python wheel (https://pypi.org/pypi/packaging/26.3/json), the
# version twine 7.0.0 brings in the release workflow. No sdist is allowed.
# PyYAML is no part of the parity oracle, so it stays out of
# tools/parity/requirements-oracle.txt and out of the oracle's venv.

--require-hashes
--only-binary :all:
